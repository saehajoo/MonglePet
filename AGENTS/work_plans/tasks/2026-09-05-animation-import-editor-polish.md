## 결정사항

- PNG 목록의 포함 여부는 체크박스, 현재 편집 대상은 행 선택, 일괄 편집 대상은 명시적인 다중 선택으로 구분한다.
- crop 결과 비교는 각 프레임을 개별 aspect-fit하지 않고 현재 가져오기 묶음의 최대 crop 크기를 공통 캔버스로 사용한다.
- 스프라이트 순서 모드를 바꿔도 포함 선택을 보존하며 클릭 순서는 현재 읽기 순서에서 시작한다.
- 편집 UI의 임시 선택·캐시는 패키지에 저장하지 않고 최종 atlas 픽셀과 기존 frame 정보만 유지한다.
- macOS 이미지 편집기는 부모 편집기를 잠시 비활성화하는 별도 AppKit 창으로 열고, 닫기 버튼도 기존 변경 취소 확인을 거친다.
- 스프라이트 창은 최소 `700×520`, PNG 창은 최소 `720×560`으로 두고 최대 크기는 제한하지 않는다. 각 창의 마지막 위치와 크기는 로컬 창 상태로만 기억한다.
- `Motion.loop`는 package 호환값으로 보존하되 제작 UI에서 선택·요약하지 않는다. 새 애니메이션은 `true`, 기존·복제 편집은 원래 값을 기록하고 제작 미리보기는 항상 순환한다.

## 검증 방법

- 크기가 다른 PNG·스프라이트 crop이 공통 캔버스에서 상대 크기와 위치를 보존하는지 확인한다.
- PNG 제외·삭제·다중 편집 후 최종 반환 배열이 화면의 포함 상태 및 순서와 같은지 확인한다.
- 순서 모드 왕복 뒤 스프라이트 선택이 유지되고 클릭 순서가 안정적인지 확인한다.
- 큰 PNG의 crop drag 중 최종 CGImage 생성이 반복되지 않고 확정 결과 픽셀이 기존 처리와 같은지 확인한다.
- 두 이미지 편집 창을 최소 크기부터 화면 크기까지 조절하고, 다시 열었을 때 마지막 위치·크기가 복원되는지 확인한다.
- 창 닫기 버튼과 편집기 취소 버튼 모두 변경 취소 확인을 거치며 부모 편집기가 함께 닫힐 때 보조 창이 남지 않는지 확인한다.
- 행동 연결 저장 실패 시 애니메이션만 남거나 기존 편집만 부분 적용되지 않는지 확인한다.
- 관련 XCTest, 전체 `MonglePetTests`, Debug 빌드와 `git diff --check`를 실행한다.

## 남은 위험 / 후속 작업

- 실제 대용량 이미지와 포인터 입력 체감 QA가 필요하다.
- 기존 애니메이션 수정은 패키지 원자 교체 후 행동 설정을 별도 저장한다. 디스크 설정 저장 실패까지 두 저장소를 함께 되돌리는 트랜잭션은 없으므로 별도 저장 아키텍처 작업이 필요하다. 애니메이션 신규 추가의 행동 연결 실패 rollback은 기존대로 유지한다.
- PNG·스프라이트 편집기의 공통 뷰 추출은 이번 동작 변경과 분리했다. 중복 UI가 다시 갈라질 때 별도 구조 정리로 진행한다.
- 현재 호스트의 UI 테스트 Runner 정지 원인을 복구하거나 Xcode에서 PNG 포함/제거, 순서 전환, 취소, 대용량 drag를 수동 확인해야 한다.
- Xcode 실제 앱에서 두 편집 창의 최소·최대 크기, 창 위치 복원, 제목 막대 닫기 확인을 수동 QA해야 한다.
- 짧은 펫 사본·정보·행동 생성·대사 입력 dialog와 가져오기·내보내기 확인은 고정 modal을 유지한다. 긴 내용 때문에 실제 불편이 확인되기 전에는 거래 확인 화면까지 독립 창으로 확대하지 않는다.
- Windows 실제 편집기 QA와 macOS 교차 왕복 전에는 플랫폼 동등 완료로 표시하지 않는다.
- 불투명 스프라이트의 배경색 변경은 사용자가 `배경 미리보기 갱신`을 눌러야 반영된다. 연속 ColorPicker 입력마다 큰 이미지 처리가 쌓이지 않는 debounce UX는 후속으로 검토한다.
