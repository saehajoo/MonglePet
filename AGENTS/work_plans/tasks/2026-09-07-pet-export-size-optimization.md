# 펫 내보내기 용량 확인과 무손실 최적화

## 상태

- 상태: in_progress
- 생성일: 2026-09-07
- 마지막 갱신: 2026-09-07

## 목표

- 설치된 펫과 편집 원본을 변경하지 않고 공유용 `.monglepet`의 PNG를 내보내기 임시 영역에서만 무손실 최적화한다.
- 내보내기 전에 현재 PNG 합계와 애니메이션별 자산 크기를, 저장 뒤에는 완성 패키지 용량을 확인할 수 있게 한다.
- 내보내기 실패를 사용자가 작업한 `내 펫` 문맥에서 바로 확인할 수 있게 한다.
- 변경되지 않은 이미지는 반복 내보내기에서 다시 최적화하지 않도록 내용 해시 기반 캐시를 둔다.

## 범위

- macOS 공유 패키지 내보내기 staging의 PNG 무손실 최적화
- 원본·결과 이미지의 크기와 디코딩 픽셀 동일성 검증
- 원본 자산 SHA-256과 최적화기 버전 기반의 삭제 가능한 캐시
- 공유 검토의 전체 예상 용량, 제한 상태와 애니메이션별 용량 상세
- `내 펫` 내보내기 실패 alert 연결
- 공통 패키지 명세와 Windows 후속 인계
- D-130: 압축 패키지 상한 30 MiB(31,457,280 bytes)를 macOS 내보내기·로컬 가져오기·웹 다운로드에 공통 적용하고 서버·Windows 인계를 갱신한다.

## 제외 범위

- 설치된 펫 자산의 재인코딩 또는 자동 수정
- 기존 펫의 아틀라스 행·열 재배치
- 펫 프레임 해상도·색상·투명도·개수 변경
- WebP 자동 변환
- macOS 버전 증가, 커밋·푸시와 Release 게시

## 열린 질문

- 없음

## 결정사항

- 강한 최적화는 편집 저장이 아니라 사용자가 요청한 공유 내보내기에서만 수행한다.
- 최적화는 원본 파일을 입력으로 하는 임시 파생물이며 캐시는 언제든 삭제 가능한 성능 보조 자료다.
- 캐시 적중 여부와 무관하게 내보내기 결과는 같은 픽셀 검증과 패키지 왕복 검증을 통과해야 한다.
- PNG를 안전하게 최적화할 수 없거나 결과가 커지면 원본 PNG를 사용한다.
- package format과 `recommended-profile.json` schema는 변경하지 않는다.
- 사용자 후속 승인에 따라 압축 상한만 30 MiB로 올린다. 해제 100 MiB·64 MiPixels·100:1·2,000 entries 등은 유지한다. WebP 출력은 별도 encoder 도입·색상·Windows 실기 검증 후 진행한다.

## 작업 순서

### 공통 계약

- [x] 내보내기 전용 파생 최적화와 원본 불변 정책을 `PET_PACKAGE.md`에 기록한다.
- [x] 용량 표시는 실제 ZIP 제한과 혼동되지 않도록 원본 PNG 합계와 완성 결과를 구분한다.

### macOS

- [x] PNG 무손실 최적화와 픽셀 검증기를 구현한다.
- [x] SHA-256·최적화기 버전 캐시를 구현하고 변경된 atlas만 다시 처리한다.
- [x] 공유 검토에 원본 자산별 용량 분석과 최적화 안내를 연결하고 저장 성공 시 완성 용량을 표시한다.
- [x] 내보내기 실패를 `내 펫`에서 alert로 표시한다.
- [x] 30 MiB 공통 상한·문구·웹 다운로드 검증과 20~30 MiB/정확한 경계 회귀 테스트를 완료한다.
- [x] 취소·실패 시 staging과 불완전한 결과가 남지 않는지 자동 검증한다.

### Windows

- [x] macOS에서 확정된 결과와 네이티브 PNG 최적화 구현 요구를 인계 문서로 작성한다.
- [ ] Windows 소스 구현·실제 QA는 Windows 환경에서 진행한다.

### 플랫폼 동등성

- [ ] 양 플랫폼의 동일 원본 패키지가 같은 픽셀·호환성 결과로 왕복되는지 후속 확인한다.

## 검증 방법

- PNG 최적화 전후 크기·RGBA 픽셀 동일성 단위 테스트
- 반복 실행 결과와 캐시 적중·최적화기 버전 무효화 테스트
- 원본 설치 파일의 해시·수정 시간이 바뀌지 않는 회귀 테스트
- 최적화 실패와 결과 증가 시 원본 fallback 테스트
- 30 MiB 경계, 내보내기 ZIP 왕복과 임시 파일 정리 테스트
- 관련 macOS 단위 테스트, Debug 빌드와 `git diff --check`
- 실제 앱에서 `새아`는 설치 원본을 수정하지 않고 별도 목적지 내보내기만 QA

## 진행 로그

- 2026-09-07: 사용자가 실제 앱에서 `새아` 내보내기 성공을 확인했다. 바탕화면 결과는 20,310,564 bytes였다. 읽기 전용 추가 실험에서 PNG 필터/압축 강화 18.20 MiB, 무손실 WebP 14.31 MiB를 측정했으나 이는 출시 구현이 아니다. 사용자 승인으로 상한 30 MiB 작업을 추가했다.
- 2026-09-07: `새아` 설치본을 읽기 전용으로 분석했다. 19개 모션·218프레임, PNG 21.34 MiB이며 고압축 ZIP도 약 21.24 MiB로 20 MiB를 초과했다. 미참조 자산은 없고 8열 atlas의 빈 셀이 전체 픽셀의 19.1%였다.
- 2026-09-07: 임시 사본 측정에서 PNG 무손실 최적화가 21.34 MiB에서 18.23 MiB로 감소했고 디코딩 RGBA 픽셀이 일치했다. 설치본과 임시 결과는 변경·보존하지 않았다.
- 2026-09-07: 앱과 같은 Swift adaptive-filter 구현으로 `새아` PNG 22,375,244 bytes를 20,339,873 bytes로 줄였다. 임시 ZIP은 20,301,959 bytes로 20 MiB 상한보다 669,561 bytes 작았고 설치본의 파일 크기·수정 시각은 전후 동일했다. 측정용 복제본은 삭제했다.
- 2026-09-07: macOS 전체 단위 테스트 565개 중 564개 성공·선택형 WebP fixture 1개 건너뜀·실패 0개, 코드 서명 없는 Debug 빌드와 `git diff --check`를 통과했다.

## 완료 결과

- D-130: macOS archive/export와 remote download의 표준 상한을 31,457,280 bytes로 통일했다. 신규 3개 경계 테스트를 포함한 관련 테스트 45개가 모두 통과했고 Debug 빌드·diff 검사를 통과했다. 기존 전체 테스트 565개 결과는 D-129 시점이며 이번에는 관련 suite만 다시 실행했다. 30 MiB 변경 후 실제 UI QA·운영 서버·Windows 적용은 남아 있다.
- macOS는 공유 검토에서 원본 PNG 합계·애니메이션별 크기를 보여주고, 사용자가 확정하면 UI 밖에서 staging PNG만 무손실 최적화한다.
- 픽셀 동일성과 더 작은 결과를 모두 만족할 때만 채택하며 실패 시 원본으로 복구한다. 설치 펫과 편집 저장은 재인코딩하지 않는다.
- 반복 내보내기는 원본 SHA-256·최적화기 버전 캐시를 사용하고 손상·구버전 캐시는 재사용하지 않는다.
- 준비·30 MiB·저장 오류는 `내 펫` alert로 표시하고 저장 성공 시 최종 `.monglepet` 용량을 표시한다.
- Windows 소스 구현·실제 양 플랫폼 QA가 남아 있어 전체 상태는 `in_progress`다.

## 남은 위험 / 후속 작업

- 구버전 앱은 20 MiB 초과 파일을 거부한다. 30 MiB 지원 양 플랫폼 배포와 서버 상한 공개 전환·업데이트 안내를 함께 준비한다. 첫 지원 릴리스 번호는 아직 정하지 않았다.
- 기존 8열 atlas를 자동 재배치하는 작업은 manifest frame 좌표를 바꾸므로 별도 단계에서 다룬다.
- 런타임 atlas 지연 로딩은 첫 재생 끊김 방지와 성능 QA가 필요한 별도 작업이다.
- 무손실 WebP는 더 큰 절감 가능성이 있지만 Windows 실기 디코딩·교차 왕복을 마치기 전 기본 출력으로 사용하지 않는다.
