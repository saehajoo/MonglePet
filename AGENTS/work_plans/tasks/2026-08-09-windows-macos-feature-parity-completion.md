# Windows macOS 기능 동등성 완성

## 상태

- 상태: completed
- 생성일: 2026-08-09
- 마지막 갱신: 2026-08-09

## 목표

- macOS 설정 화면에서 제공하는 펫 편집·이동·행동 루틴·말풍선·자동 규칙 기능을 Windows 네이티브 앱에서도 같은 사용자 결과와 같은 `.monglepet` 의미로 제공한다.
- 저속 이동의 정수 반올림 손실, 다중 모니터 경계 고착과 끊기는 이동을 수정한다.
- 두 플랫폼에서 만든 `.monglepet` 패키지가 동일한 manifest·애니메이션 프레임·권장 프로필 의미로 가져오기와 내보내기를 왕복하도록 유지한다.

## 현재 차이와 개선 범위

### 펫·패키지

- Windows에는 현재 애니메이션 목록 선택·상세 미리보기와 추가·수정·삭제가 없다.
- Windows에는 새 펫 만들기, 펫 정보 수정, 읽기 전용 가져온 펫의 편집 가능한 사본 만들기 흐름이 없다.
- Windows 버튼 문구와 구성이 macOS의 `MonglePet 패키지 / 패키지 가져오기 / 현재 펫 내보내기`와 다르다.
- Windows의 삭제·내보내기 가능 여부를 내장 펫, 가져온 읽기 전용 펫, 사용자 편집 가능 펫 상태에 맞게 구분해야 한다.

### 이동

- Windows는 모든 모드의 설정을 한꺼번에 표시하고, macOS처럼 선택 모드에 필요한 섹션만 표시하지 않는다.
- Domain에는 공통·4방향·8방향 애니메이션 필드가 있지만 Windows UI는 공통 fallback 하나만 편집한다.
- 사용자 지정 이동 영역의 정규화 좌표·크기 편집 UI가 없다.
- 위치 고정 안내, 모드별 이동 감각·범위·자유 이동·마우스 따라가기·도망가기·상호작용 구성이 macOS와 다르다.
- 런타임은 매 tick의 소수점 이동량을 정수 HWND 위치에서 다시 시작해 저속에서 진행량을 잃고, `모든 화면` 이동 중 매 프레임 현재 모니터 작업 영역으로 clamp해 다른 모니터로 건너지 못할 수 있다.

### 행동 루틴

- Windows는 macOS의 `설정 대상 펫 / 편집할 행동 루틴 / 새 행동 루틴 만들기 / 재생 설정 / 애니메이션 단계` 흐름보다 한 화면에 밀집돼 있다.
- 단계별 애니메이션·반복·순서·삭제의 제약과 설명을 동일하게 정리해야 한다.

### 말풍선

- Windows는 행동 대사와 주기 대사를 하나의 목록·폼으로 섞어 표시하고, macOS의 별도 추가·수정 흐름 및 모양·위치 편집 흐름과 다르다.
- 테마·꼬리·위치 값은 저장 버튼 전 외부 상태 갱신이 오면 저장값으로 다시 덮여 `Off`처럼 보일 수 있다.
- 말풍선 전체 사용 여부와 주기 사용 여부에 따른 하위 컨트롤 활성화가 불완전하다.
- 실제 펫·말풍선·꼬리·상대 위치가 함께 보이는 미리보기와 저장/취소 draft 경계를 보완해야 한다.

### 자동 규칙

- 입력 없음 조건은 Domain과 편집 폼에 존재하지만 별도 `입력 없음 규칙 추가` 섹션이 없어 발견하기 어렵다.
- macOS처럼 앱 규칙 추가, 입력 없음 규칙 추가, 등록된 규칙을 분리하고 활성·우선순위·대상 루틴 편집을 명확히 해야 한다.

## 범위

- Windows 펫 편집 서비스와 WinUI 펫·애니메이션 편집 대화상자

- 모드별 이동 설정 UI, 방향별 애니메이션과 사용자 지정 영역 편집
- 소수점 위치 누적과 다중 모니터 횡단이 가능한 이동 런타임
- 행동 루틴, 말풍선, 자동 규칙 설정 UI와 저장 생명주기
- 관련 단위·통합 테스트, Debug·Release·MSIX와 실제 앱 QA

## 열린 질문

- 없음. 제품 동작은 현재 macOS 구현과 공통 명세를 기준으로 한다.

## 결정사항

- UI는 WinUI 컨트롤을 사용하지만 탭별 섹션 이름, 노출 조건, 가능/불가능 상태와 사용자 결과는 macOS 기준과 맞춘다.
- 내장 펫은 편집·삭제·내보내기할 수 없고, 가져온 패키지는 읽기 전용으로 유지하며 편집하려면 독립 사본을 만든다.
- 사용자 펫 편집 marker는 macOS와 같은 `monglepet-editor.json` schema-v1 의미를 사용하되 공유 내보내기에는 포함하지 않는다.
- 패키지 편집은 임시 디렉터리에서 전체 loader 검증 후 동일 설치 UUID를 원자적으로 교체한다.
- 이동 런타임은 논리 좌표를 `double`로 누적하고 HWND 적용 시에만 반올림한다. `모든 화면`은 가상 데스크톱 횡단을 허용하고 선택 모니터·사용자 영역만 해당 경계로 clamp한다.
- 말풍선 대사와 테마 편집은 저장 전 draft를 유지하고 저장 또는 취소가 명확한 편집 흐름을 사용한다.

## 검증 방법

- 저속 20px/s 이동이 여러 tick의 소수점 진행량을 잃지 않는지 단위 테스트
- 간격이 있거나 음수 좌표인 두 모니터 사이를 모든 화면 모드에서 횡단하는지 테스트
- 선택 모니터와 사용자 지정 영역에서는 경계를 벗어나지 않는지 테스트
- 공통 하나·4방향·8방향 이동 애니메이션 설정 JSON 왕복과 실제 선택 테스트
- 사용자 펫 생성, 메타데이터 수정, 애니메이션 추가·이름/프레임/간격 수정·삭제 제약과 원자적 교체 테스트
- Windows 내보내기 → Windows 재가져오기 및 공통 fixture 왕복 검증
- 행동·주기 대사 분리, 꼬리 Off/On, 테마·위치 저장/취소와 재실행 복원 테스트
- 앱 규칙과 입력 없음 규칙 추가·수정·삭제·우선순위 테스트
- Windows 전체 xUnit, x64 Debug·Release·MSIX 빌드
- 실제 앱에서 네 이동 모드, 느린 이동, 모니터 횡단과 설정창 시각 QA

## 완료 결과

- Windows 설정에 macOS와 대응하는 펫 애니메이션 편집, 패키지 가져오기·현재 펫 내보내기, 사용자 펫 생성·정보 수정·사본·삭제 흐름을 제공한다.
- 네 이동 방식별로 필요한 설정만 표시하고 공통·4방향·8방향 애니메이션, 사용자 지정 영역과 쓰다듬기 설정을 편집한다.
- 저속 이동의 소수점 진행량이 보존되며 모든 화면 이동이 모니터별 경계에 고착되지 않는다.
- 행동 루틴, 앱 규칙·입력 없음 규칙, 행동·주기 대사와 말풍선 모양·위치 설정을 macOS의 정보 구조에 맞췄다.
- 자동화 검증과 빌드·패키지 생성은 완료했다. 실제 장치 특성에 좌우되는 항목은 아래 수동 QA로 인계한다.

## 남은 위험 / 후속 작업

- PNG atlas 생성은 WinRT 이미지 디코더·인코더를 사용하므로 투명도, 최대 크기와 다중 프레임 메모리 사용을 실제 이미지로 검증한다.
- 혼합 DPI 모니터 횡단은 자동 좌표 테스트 외에 실제 Windows 배율 조합에서 확인한다.
- macOS에서 내보낸 실제 사용자 패키지를 Windows에서 편집·내보낸 뒤 macOS로 다시 가져오는 교차 왕복은 두 앱을 함께 사용하는 수동 QA에서 확인한다.
- 설정 창의 실제 픽커·대화상자, 느린 속도의 물리 모니터 횡단, 말풍선 값의 탭 전환·재실행 복원은 사용자 시각 QA에서 확인한다.
