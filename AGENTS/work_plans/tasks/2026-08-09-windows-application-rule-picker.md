# Windows 자동 규칙 앱 선택기

## 상태

- 상태: completed
- 생성일: 2026-08-09
- 마지막 갱신: 2026-08-09

## 목표

- 사용자가 Windows 내부 앱 식별자를 알지 못해도 현재 일반 창이 열린 앱이나 직접 선택한 실행 파일로 앱 자동 규칙 대상을 정할 수 있게 한다.
- 기존 `pfn:`·`exe:` 규칙과 개인정보 최소 수집 원칙을 유지한다.

## 범위

- 실행 중 일반 앱의 이름·아이콘·PFN 또는 실행 파일 식별자 후보
- 최상위 일반 창이 없는 백그라운드 프로세스, MonglePet 자체와 중복 식별자 제외
- 후보 필터·중복 제거·정렬을 담당하는 순수 모델과 단위 테스트
- 표준 파일 선택기를 통한 `.exe` 선택과 표시 이름·아이콘 추출
- 자동 규칙 편집 폼의 대상 앱 선택 dialog, 새로 고침과 선택 결과 요약
- 기존 직접 입력·현재 전면 앱 채우기 경로 유지
- packaged Release 실제 UI QA와 재실행 복원

## 제외 범위

- 전체 디스크, Program Files, 레지스트리와 시작 메뉴의 설치 앱 자동 스캔
- 앱 이름·아이콘·경로·실행 이력의 영구 저장
- 브라우저 URL, 창 제목·문서명과 실제 입력 내용 조회
- 설정 schema 변경

## 열린 질문

- 없음

## 결정사항

- 실행 앱 후보는 보이는 소유자 없는 최상위 일반 창의 프로세스만 열거하고 창 제목은 읽지 않는다.
- 후보를 만들 때 실행 파일 경로와 파일 버전 정보는 이름·아이콘을 표시하는 동안 메모리에서만 사용하고 설정에는 기존 식별자만 저장한다.
- 전체 설치 앱 탐색 대신 사용자가 표준 파일 선택기에서 `.exe`를 명시적으로 고르는 경로를 제공한다.
- 목록의 아이콘 추출 실패는 후보 자체를 숨기지 않고 일반 앱 glyph로 복구한다.
- MonglePet의 PFN과 실행 파일 식별자는 선택 후보에서 모두 제외한다.

- [x] 6단계: Windows·동등성·테스트 문서와 계획 완료

## 검증 방법

- 일반 창 여부, MonglePet 제외, 식별자 정규화, 중복 선호와 이름 정렬을 운영체제 API 없이 xUnit으로 확인한다.
- Activity·Core·Packages·PetLibrary·Settings 전체 xUnit과 x64 Debug·Release 빌드를 실행한다.
- 실제 packaged Release에서 MonglePet 외 실행 앱을 목록에서 선택해 규칙·LocalState에 반영되는지 확인한다. `.exe` 검사는 자동 테스트하고 시스템 파일 선택 대화상자의 실제 선택은 수동 QA로 남긴다.
- QA 뒤 앱 프로세스, 테스트 앱, 패키지 등록, LocalState와 임시 파일이 남지 않는지 확인한다.

## 진행 로그

- 2026-08-09: macOS 앱 선택기, Windows PFN·실행 파일 식별자와 현재 규칙 편집 UI를 분석하고 디스크 스캔 없는 실행 앱·명시적 `.exe` 선택 범위를 확정했다.
- 2026-08-09: 후보 정규화·필터·중복 선호·이름 정렬 모델과 9개 테스트를 추가해 Activity 테스트 18개를 통과했다.
- 2026-08-09: 창 제목 없이 visible·ownerless·non-tool 최상위 창의 프로세스를 열거하고 PFN·실행 파일 식별자와 메모리 전용 표시 metadata를 만드는 Win32 catalog를 구현했다.
- 2026-08-09: 지연 아이콘, 새로 고침, 실행 파일 선택을 포함한 ContentDialog와 규칙 폼 선택 요약을 연결하고 Windows Debug 앱 프로젝트 빌드를 경고 없이 통과했다.
- 2026-08-09: `.exe` 검사 성공·누락·잘못된 형식·MonglePet 자체 제외 테스트를 보강해 Activity 테스트 21개를 통과했다.
- 2026-08-09: packaged Release에서 MonglePet을 제외한 실행 앱 5개와 이름·아이콘·식별자 표시를 확인하고 Notepad를 골라 PFN 규칙으로 저장했다. JSON에는 이름·경로가 남지 않았고 충돌·임시 파일은 없었다.
- 2026-08-09: x64 Debug·Release 전체 빌드와 총 99개 테스트를 통과하고 QA 프로세스·Notepad·패키지 등록·LocalState를 제거했다.
- 2026-08-09: 실제 사용자 QA에서 표준 파일 선택기로 KakaoTalk 실행 파일을 골라 `exe:kakaotalk.exe` 저장과 전면 앱 전환 시 `dd` 루틴 실행을 확인했다. `cmd.exe`는 Windows Terminal이 창을 호스팅하므로 직접 전면 앱으로 감지되지 않는 경계를 확인했다.

## 완료 결과

- 실행 중 일반 앱을 이름·아이콘·PFN/실행 파일 식별자로 선택하고 기존 자동 규칙 폼에 반영할 수 있다.
- background·tool·owned·cloaked 창, MonglePet 자체와 중복 식별자를 제외하며 창 제목은 읽지 않는다.
- `.exe`를 명시적으로 고르는 표준 파일 선택 경로와 검사 경계를 제공하고, 직접 입력·현재 전면 앱 채우기도 유지한다.
- 영구 설정에는 기존 식별자만 저장하며 선택용 이름·아이콘·실행 파일 경로와 실행 이력은 저장하지 않는다.

## 남은 위험 / 후속 작업

- 패키지 앱 또는 보호된 실행 파일은 이름·아이콘 metadata 접근이 거부될 수 있으므로 식별자와 일반 glyph 폴백을 유지한다.
- Windows Terminal처럼 선택한 실행 파일과 실제 최상위 창 소유 프로세스가 다른 앱은 호스트 앱 식별자를 사용해야 한다.
