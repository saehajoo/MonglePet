# Phase 9C 방향별 이동 애니메이션

## 상태

- 상태: completed
- 생성일: 2026-07-29
- 마지막 갱신: 2026-07-29

## 목표

- 실제 펫 이동 방향을 안정적으로 감지해 방향에 맞는 애니메이션을 표시한다.
- 마우스 따라가기와 자유 이동이 각각 독립된 방향별 애니메이션 설정을 갖게 한다.
- 기본 사용자는 기존처럼 애니메이션 하나만 선택할 수 있고, 원하는 사용자만 4방향과 선택적 대각선 설정을 사용하게 한다.
- 기존 설정과 `.monglepet` 권장 프로필을 손실 없이 호환한다.
- 내보내기·가져오기 전에 방향 설정을 포함해 실제로 공유·적용되는 펫별 설정을 사용자가 확인할 수 있게 한다.

## 범위

- 실제 적용된 패널 좌표 변화량 기반 4방향·8방향 분류
- 방향 경계에서 반복 전환되지 않게 하는 히스테리시스와 정지 상태 처리
- 마우스 따라가기용·자유 이동용 독립 애니메이션 설정
- 공통 하나, 방향별 4개와 선택적 대각선 4개의 애니메이션 선택 UI
- 방향별 항목 미지정·누락 시 단계적 fallback
- 이동 활동과 재생 조정기의 방향 전달, 상호작용 우선순위와 행동 복귀 유지
- 로컬 설정 schema-v5, 이전 schema-v4 마이그레이션과 미래 버전 쓰기 차단
- `recommended-profile.json` schema-v2, 기존 schema-v1 읽기와 방향 설정 공유
- 내보내기·가져오기 검토 화면의 이동·행동·자동 규칙 상세 요약
- 새 펫별 설정이 추가될 때 권장 프로필 누락을 검출하는 공유 범위 회귀 테스트
- 애니메이션 이름 변경·삭제 시 모든 방향 참조 갱신·복구
- Domain, 마이그레이션, 공유 왕복, 설정 UI와 런타임 테스트

## 제외 범위

- 이미지 또는 애니메이션의 좌우·상하 자동 반전
- 방향 애니메이션 자동 생성이나 기존 이미지 보정
- 목표를 바라보는 정지 방향, 시선 추적과 회전 애니메이션
- 16방향과 사용자가 임의 각도를 추가하는 기능
- 방향별 속도·프레임 시간·이동 물리 설정
- 펫 패키지 `pet.json`의 모션 manifest 형식 변경
- Codex v2 `look-*` 단일 프레임을 방향 이동 애니메이션으로 자동 연결

## 현재 구조 검토

- `PetMovementSettings`는 `cursorFollowingMotionID`와 `freeRoamingMotionID` 하나씩만 저장한다.
- `PetMovementController`는 실제 좌표를 적용하기 전후의 원점을 알고 있지만 `PetMovementActivity`에는 `isMoving`과 `motionID`만 전달한다.
- `PetPlaybackCoordinator`는 이동 중 모션 하나를 반복 표시하고, 쓰다듬기 같은 상호작용이 있으면 이를 우선 표시한 뒤 최신 이동 또는 행동으로 돌아간다.
- 로컬 설정은 schema-v4, 선택적 권장 프로필은 schema-v1이므로 방향 설정을 안전하게 공유하려면 각각 다음 버전이 필요하다.

- 현재 직렬화 기준으로 기존 `BehaviorProfile`의 공유 대상 필드가 실제 패키지에서 빠진 문제는 발견되지 않았다.
- 가장 큰 누락은 데이터가 아니라 검토 UI다. 사용자는 전체 프로필을 적용하지만 현재 화면에서는 루틴·규칙·이동 세부값을 충분히 확인할 수 없다.
- 내보내기와 가져오기가 서로 다른 요약을 만들지 않도록 공통 `RecommendedProfileSummary` 모델을 두고 두 화면이 같은 데이터를 표시하게 한다.
- 검토 화면에는 `이 패키지에 포함되지 않는 현재 기기 설정` 안내를 두어 위치·범위·투명도·클릭 통과가 공유된다고 오해하지 않게 한다.
- 이후 `BehaviorProfile`에 필드가 추가되면 공유 대상 또는 로컬 제외 사유를 반드시 선택하게 하고, 모든 공유 대상이 codec 왕복에서 동일한지 검증하는 non-default fixture 테스트를 추가한다.

## 제안 모델

```swift
enum MovementDirection {
    case left
    case right
    case up
    case down
    case upLeft
    case upRight
    case downLeft
    case downRight
}

struct MovementAnimationSettings {
    let fallbackMotionID: String?
    let usesDirectionalMotions: Bool
    let usesDiagonalMotions: Bool
    let directionMotionIDs: DirectionalMotionIDs
}

struct PetMovementSettings {
    // 기존 이동 값
    let cursorFollowingAnimation: MovementAnimationSettings
    let freeRoamingAnimation: MovementAnimationSettings
}
```

- schema-v4의 `cursorFollowingMotionID`, `freeRoamingMotionID`는 각각 새 설정의 `fallbackMotionID`로 옮긴다.
- 마이그레이션된 설정은 `usesDirectionalMotions: false`로 시작해 현재 표시 결과를 그대로 유지한다.
- 방향 ID는 코드와 JSON에서 `left`, `right`, `up`, `down`, `upLeft`, `upRight`, `downLeft`, `downRight`의 명시적 이름을 사용한다.
- 저장 DTO는 방향 키가 누락돼도 `nil`로 읽을 수 있는 명시적 필드 구조를 사용하고 임의 문자열 dictionary는 사용하지 않는다.

## 방향 판정과 fallback 제안

- 목표 방향이 아니라 macOS 패널에 실제 적용된 `새 원점 - 이전 원점`을 사용한다.
- 화면 좌표의 `+x`는 오른쪽, `+y`는 위쪽으로 해석한다.
- 방향별 설정이 꺼져 있으면 기존처럼 `fallbackMotionID` 하나를 사용한다.
- 4방향 모드에서는 전체 각도를 90도 구간 네 개로 분류한다.
- 대각선 설정을 켜면 전체 각도를 45도 구간 여덟 개로 분류한다.
- 현재 방향 구간을 벗어나더라도 추가 각도 여유를 넘어설 때만 방향을 바꾸는 히스테리시스를 적용한다.
- 대각선의 정확한 애니메이션이 없으면 이동량이 더 큰 축의 상·하·좌·우 방향을 사용하고, 두 축이 같으면 좌·우 방향을 우선한다.
- 해당 기본 방향도 없으면 모드의 `fallbackMotionID`, 이것도 없거나 펫에서 찾을 수 없으면 현재 행동 표시를 유지한다.
- 정지 히스테리시스가 끝나면 이동 표시는 해제하되 마지막 방향은 다음 이동 시작의 경계 안정화를 위해 런타임 메모리에만 보존할 수 있다.
- 해석 결과 모션 ID가 이전과 같으면 방향 값만 바뀌어도 프레임 재생을 재시작하지 않는다.

## 설정 UI 제안

- 위치: `설정 > 이동`의 마우스 따라가기·자유 이동 각 섹션에서 기존 `이동 중 애니메이션` 자리를 확장한다.
- 위치 고정에는 방향 설정을 표시하지 않는다.
- `애니메이션 방식`은 `공통 하나`와 `방향별` 중 선택하며 기본값은 `공통 하나`다.
- 공통 하나에서는 현재와 같은 단일 picker를 유지한다.
- 방향별에서는 fallback인 `기본 이동 애니메이션`과 상·하·좌·우 picker를 표시한다.
- `대각선도 따로 설정`을 켠 경우에만 네 개의 대각선 picker를 추가한다.
- 방향 목록은 좁은 설정창에서 잘리지 않도록 방향 아이콘·이름과 picker를 가진 세로 Grid 또는 접이식 영역으로 제공한다.
- 각 방향은 `지정 안 함`을 허용하고 실제 fallback 결과를 짧은 도움말로 설명한다.
- 마우스 따라가기와 자유 이동 설정을 한 화면에서 동시에 펼치지 않고 현재 선택한 이동 모드의 설정만 표시한다.

## 공유와 호환성 제안

- 방향 애니메이션은 펫의 모션 ID를 참조하는 제작자 의도이므로 선택적 권장 프로필에 포함한다.
- 새 내보내기는 `recommended-profile.json` schema-v2를 사용하고 schema-v1은 기존 단일 이동 애니메이션으로 계속 읽는다.
- 내보내기 검토에는 각 이동 모드의 공통/방향별 사용 여부와 실제 방향-애니메이션 연결을 표시한다.
- 가져오기 검토에도 동일한 내용을 표시하고, 권장 설정을 적용하지 않는 선택을 계속 제공한다.
- 행동 루틴·자동 규칙·이동 설정은 공통 요약 모델을 통해 내보내기와 가져오기에서 같은 수준으로 확인할 수 있게 한다.
- 미래 권장 프로필 schema를 지원하지 못하면 기존 정책대로 펫만 설치하고 권장 설정은 적용하지 않는다.
- 로컬 설정은 schema-v5로 올려 이전 앱이 알 수 없는 방향 필드를 읽은 뒤 저장하면서 삭제하는 일을 막는다.
- 펫 자체의 이미지·모션 manifest는 바뀌지 않으므로 `pet.json.formatVersion`은 유지한다.
- 방향별 모션 ID도 기존 이동·쓰다듬기 참조처럼 현재 펫의 실제 모션인지 검증하고, 이름 변경 시 함께 바꾸며 삭제 시 해당 방향만 `nil`로 해제한다.

## 확정된 사항

- 마우스 따라가기와 자유 이동은 각각 독립된 방향 애니메이션 설정을 갖는다.
- 기존 모드별 단일 애니메이션은 fallback이자 완전한 호환 경로로 유지한다.
- 이미지와 애니메이션 자동 반전은 제공하지 않는다.
- 방향 애니메이션이 없어도 이동 좌표, 현재 행동과 기존 펫 패키지는 정상 동작해야 한다.
- 방향별 설정은 선택적 권장 프로필과 펫 내보내기·가져오기에 포함하며 양쪽 검토 화면에서 확인할 수 있어야 한다.
- 위치·이동 범위·크기·투명도·클릭 통과 같은 기기 로컬 표시 설정은 패키지에 포함하지 않는다.

## 검증 방법

- 정확한 좌·우·상·하·대각선 벡터와 각 구간 경계 전후를 표 기반 단위 테스트로 확인한다.
- 저속의 1pt 미만 이동, 정지 반경, 정지 히스테리시스와 화면 전환에서도 방향이 안정적인지 확인한다.
- 방향 경계 주변의 작은 벡터 변화가 매 tick 애니메이션을 재시작하지 않는지 확인한다.
- 4방향, 8방향, 미지정 방향, 누락 모션과 단일 fallback의 선택 순서를 검증한다.
- 이동 중 쓰다듬기는 계속 우선 표시하고 완료 뒤 최신 방향 애니메이션으로 복귀하는지 확인한다.
- schema-v4 fixture가 기존 두 이동 애니메이션을 보존한 schema-v5로 변환되고 재실행 뒤 같은 결과를 내는지 확인한다.
- 손상된 개별 방향 ID는 해당 항목만 복구하며 다른 이동·행동 설정을 보존하는지 확인한다.
- 모션 이름 변경·삭제가 두 이동 모드의 모든 방향 참조에 반영되는지 확인한다.
- 권장 프로필 v1을 기존 의미로 읽고 v2 방향 설정의 내보내기·가져오기·설치 적용을 왕복 검증한다.
- 모든 공유 대상 값을 기본값이 아닌 값으로 채운 fixture가 codec·내보내기·가져오기 후 동일하며, 기기 로컬 설정은 패키지에 기록되지 않는지 확인한다.
- 내보내기와 가져오기 검토 화면이 공통 요약으로 루틴·자동 규칙·이동값·방향 연결을 동일하게 표시하는지 확인한다.
- 실제 앱에서 마우스 따라가기와 자유 이동 각각 좌·우·상·하 및 선택적 대각선을 확인한다.
- 방향별 설정을 사용하지 않는 기존 펫과 기존 설정의 CPU·재생 동작이 현재 기준에서 악화되지 않는지 확인한다.

## 완료 결과

- 실제 이동 방향에 따른 4방향·선택적 8방향 애니메이션을 두 자동 이동 모드에 독립적으로 설정할 수 있다.
- 기존 schema-v4와 권장 프로필 v1의 단일 이동 애니메이션을 보존하면서 schema-v5·권장 프로필 v2로 안전하게 확장했다.
- 내보내기·가져오기에서 동일한 상세 요약을 사용해 공유되는 행동·자동 규칙·이동 설정과 제외되는 기기 설정을 구분한다.
- 전체 단위 테스트, Debug 빌드와 실제 앱 수동 QA를 완료했다.

## 남은 위험 / 후속 작업

- 방향 분류 경계가 민감하면 짧은 이동에서 애니메이션이 반복 전환될 수 있으므로 히스테리시스 수동 조정이 필요하다.
- 모드별 최대 9개 참조가 생기므로 설정 UI가 길어지거나 펫 제작 부담이 커지지 않게 점진적으로 노출해야 한다.
- 방향별 모션을 많이 가진 펫에서 애니메이션 교체 비용과 CPU 변화를 Release 빌드로 확인해야 한다.
- Codex v2 `look-*` 모션 자동 연결은 의미와 프레임 구조가 이동 애니메이션과 다르므로 별도 후속 결정으로 남긴다.
- 픽셀 아트 렌더링은 현재 사용자 전역 설정이지만 펫 제작자가 권장값을 제공할 필요가 생기면 로컬 설정 강제 공유가 아닌 별도 manifest 힌트로 설계해야 한다.
