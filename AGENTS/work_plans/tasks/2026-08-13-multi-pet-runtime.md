# 멀티펫 런타임과 활성 펫 관리

## 상태

- 상태: in_progress
- 생성일: 2026-08-13
- 마지막 갱신: 2026-08-25

## 목표

- 사용자가 설치한 펫을 한 마리 이상 동시에 데스크톱에 표시하고 각각 독립적으로 제어한다.
- 사용자에게 고정된 동시 표시 마릿수 제한을 강제하지 않는다.
- 많은 펫으로 성능이 저하되거나 비정상 종료가 발생해도 설정과 펫 파일을 잃지 않고 안전하게 복구한다.
- macOS에서 제품 동작과 공통 설정 계약을 먼저 확정한 뒤 Windows 네이티브 앱에 같은 사용자 결과를 반영한다.
- 멀티펫을 별도 부가 기능이 아니라 설정의 첫 진입점에서 관리할 수 있는 핵심 기능으로 제공한다.

## 범위

- 설치된 펫 콘텐츠, 로컬 설치 사본과 화면에 표시되는 펫 인스턴스의 식별자 분리
- settings schema-v11 멀티펫 인스턴스 목록과 schema-v10 단일 펫 설정의 무손실 마이그레이션
- 인스턴스별 표시 상태, 위치, 크기, 투명도, 클릭 통과, 이동, 행동, 쓰다듬기와 말풍선 런타임
- 앱 전체에서 공유하는 활동·포인터·모니터 snapshot과 이미지·알파 마스크 캐시
- 활성 펫 관리, 펫 보관함과 선택한 펫 설정을 구분하는 설정 정보 구조 개편
- 전체 펫과 개별 펫을 위한 상태 메뉴·notification area 빠른 제어
- 자원 경고, 사용자 제어 일시정지, 단계적 시작 복원과 비정상 종료 안전 시작
- macOS 구현·검증 후 Windows Domain과 네이티브 UI·오버레이 후속 반영
- 멀티펫 기능 릴리스에 맞춘 앱 버전·빌드 번호와 기존 패키지 호환 정책 유지

## 제외 범위

- 펫끼리 충돌하거나 밀어내는 물리 엔진
- 펫끼리 대화하거나 서로의 행동을 직접 트리거하는 상호작용
- 여러 펫의 배치 전체를 `.monglepet` 하나로 공유하는 기능
- 클라우드 동기화와 여러 기기 사이 활성 펫 배치 복원
- 성능 저하만을 이유로 사용자 펫을 자동 중지·숨김·삭제하거나 설정을 바꾸는 동작
- macOS에서 WinUI 3·Win32 HWND·Windows App SDK 통합 실행과 실제 Windows 성능 QA

## 결정사항

- 일반 사용자가 볼 수 있는 고정 최대 마릿수는 두지 않는다.
- 멀티펫 기능의 macOS·Windows 공통 마케팅 버전은 `1.1.0`으로 올린다. 플랫폼별 빌드 번호는 각 배포 이력에 맞게 별도로 증가시킨다.
- 손상되거나 비정상적으로 큰 설정 파일로 무제한 창 생성을 시도하지 않도록 파일 크기·구조 검증과 구현상 방어 한계는 유지한다. 이는 제품의 마릿수 제한이 아니라 입력 안전 경계다.
- `packageID`는 펫 콘텐츠, `installationID`는 로컬 설치 사본, 새 `instanceID`는 화면에 표시되는 펫 하나를 식별한다.
- 같은 설치 펫도 서로 다른 `instanceID`로 여러 번 추가할 수 있게 데이터 구조를 설계한다.
- 각 인스턴스는 고유한 행동 프로필과 표시·이동·행동·말풍선 상태를 독립적으로 소유한다. 한 인스턴스의 설정 변경은 같은 원본 펫의 다른 인스턴스에 전파하지 않는다.
- 설치 패키지의 이미지와 모션 정의는 읽기 전용으로 공유한다. 특정 인스턴스에서 이름·애니메이션 같은 원본 정의를 편집하면 새 package ID의 편집 가능한 사본을 만들고 그 인스턴스만 새 설치본에 연결하는 copy-on-write 흐름을 사용한다.
- `.monglepet`은 계속 펫 하나와 선택 권장 프로필을 교환하는 형식으로 유지하며 활성 인스턴스의 화면 좌표와 장면 구성은 포함하지 않는다.
- 현재 동작대로 새로 만들거나 내보낸 패키지의 `createdWithMonglePetVersion`과 `minimumMonglePetVersion`은 현재 앱 버전으로 함께 기록한다. 사용자 펫 자체의 `pet.json.version`은 제작자가 정하는 콘텐츠 버전으로 앱 버전과 분리한다.
- 전면 앱·입력 없음·잠금·절전·포인터·모니터 관찰은 앱 전체에서 한 번만 수행하고 각 인스턴스에 snapshot을 전달한다.
- 성능 경고는 펫 추가를 차단하지 않으며 CPU·메모리 기준을 넘어도 앱이 임의로 인스턴스를 중지·숨김·삭제하지 않는다. 일시정지와 제거는 사용자가 선택하고 원본 설정과 펫 파일은 보존한다.
- 펫 창의 앞뒤 순서는 영속적인 `displayOrder`로 사용자가 직접 정한다. 마지막 클릭·쓰다듬기·드래그는 저장된 순서를 바꾸지 않는다.
- 펫끼리의 충돌 판정과 말풍선끼리의 충돌 회피는 후속 검토로 분리하고 마우스 도망가기는 인스턴스마다 독립적으로 판단한다.
- 기존 가로 탭에 `멀티펫` 하나를 더 붙이지 않는다. macOS는 사이드바 기반 설정 구조, Windows는 WinUI NavigationView 기반의 동등한 정보 구조를 사용한다.
- 구현 순서는 macOS 기준 확정, 공통 schema·fixture 정리, Windows 후속 반영 순이다.

## 제안 설정 모델

schema-v11의 구체적인 DTO는 1단계에서 확정하지만 다음 책임 분리를 기준으로 한다.

```json
{
  "schemaVersion": 11,
  "selectedPetInstanceID": "instance-uuid",
  "activePetInstances": [
    {
      "instanceID": "instance-uuid",
      "installationID": "installation-uuid-or-null-for-built-in",
      "nickname": "몽글이 2",
      "presentation": "awake",
      "overlay": {},
      "behaviorProfileID": "profile-uuid",
      "displayOrder": 0
    }
  ],
  "behaviorProfiles": []
}
```

- schema-v10의 `selectedPetInstallationID`, `lastUserPresentation`, `overlay`와 활성 행동 프로필은 첫 번째 v11 인스턴스로 옮긴다.
- 기존에 선택되지 않았던 설치 펫의 행동 프로필도 버리지 않고 프로필 저장소에 유지한다.
- 프로필에 별도 UUID를 두어 같은 설치 펫의 여러 인스턴스도 항상 독립적으로 편집한다. 다시 추가할 때 기존 설정을 선택적으로 복사하더라도 이후 변경은 공유하지 않는다.
- `nickname`은 같은 원본 펫의 여러 인스턴스를 구분하는 선택적 사용자 이름이며 패키지의 원본 펫 이름을 변경하지 않는다.
- `selectedPetInstanceID`는 설정 화면의 편집 대상일 뿐 유일한 실행 펫이나 소유권을 의미하지 않는다.
- 설치 펫 삭제 시 이를 참조하는 모든 인스턴스를 먼저 검토하고 사용자가 제거 또는 다른 펫 교체를 선택하게 한다.

## 자원 보호와 복구 정책

### 평상시

- 펫 수가 늘어도 추가 버튼을 비활성화하지 않는다.
- 여러 펫이 활성일 때만 낮은 빈도의 앱 자체 CPU·메모리·프레임 지연 관찰을 시작한다.
- 설치 ID와 atlas 경로 또는 콘텐츠 해시 기준으로 디코딩 이미지, Composition surface와 알파 마스크를 공유한다.
- 고정·대기·재움·숨김 상태에는 이동 tick과 불필요한 포인터 관찰을 중지한다.
- 여러 마우스 따라가기 인스턴스에는 안정적인 커서 상대 오프셋을 부여해 같은 위치에 완전히 겹치지 않게 한다.

### 성능 저하

- 측정 기준을 넘으면 `활성 펫` 화면과 상태 메뉴에 비차단 경고를 표시한다.
- 경고에는 현재 활성·이동 중 펫 수, CPU·메모리 상태, `모두 일시정지`와 개별 펫 재우기 진입점을 제공한다.
- 사용자가 계속 추가하거나 실행하는 선택은 허용한다.
- 일반 CPU 상승만으로 임의의 펫을 자동으로 숨기거나 삭제하지 않는다.

### 비정상 종료와 사용자 복구

- 운영체제 메모리 압력이나 앱 자체 부하가 높아도 앱이 임의로 펫을 정지·숨김·삭제하지 않고 경고와 사용자 제어만 제공한다.
- 상태 메뉴와 설정에 항상 `모든 펫 일시정지`와 `안전하게 다시 시작` 경로를 둔다.
- 앱 시작 시 인스턴스를 한꺼번에 만들지 않고 저장된 순서대로 하나씩 활성화하며 각 시작 전후를 별도 복구 상태에 기록한다.
- 이전 실행이 인스턴스 활성화 도중 비정상 종료됐으면 다음 실행은 펫 복원 전에 안전 시작 화면을 연다. 사용자가 복원·일시정지·제거 대상을 직접 선택한다.
- 반복 실패한 인스턴스도 자동 삭제하지 않으며 사용자가 설치 펫 검증, 설정 초기화, 비활성 유지 또는 제거를 선택한다.

## UX·UI 정보 구조

현재 6개 가로 탭은 멀티펫용 탭을 추가하면 폭과 대상 구분이 더 어려워지므로 다음 구조를 권장한다.

### 공통 정보 구조

- 데스크톱
  - `활성 펫`: 첫 화면. 활성 인스턴스 카드·미리보기·추가·재우기·제거·전체 일시정지·성능 상태
  - `일반`: 로그인 실행, 앱 정보와 앱 전체 설정
- 선택한 펫
  - `표시 및 이동`: 위치, 크기, 투명도, 클릭 통과, 이동 범위와 이동 애니메이션
  - `행동 루틴`
  - `말풍선`
  - `자동 규칙`
- 보관함
  - `펫 보관함`: 설치·가져오기·내보내기·새 펫 만들기·정보와 애니메이션 편집·삭제

### 활성 펫 화면

- 상단에는 `펫 추가`, `모두 깨우기/재우기`, `모두 일시정지`만 주요 행동으로 둔다.
- 각 카드는 펫 미리보기, 사용자 구분 이름, 원본 펫 이름, 깨움 상태, 이동 모드와 현재 화면을 표시한다.
- 카드 순서를 드래그해 펫의 영속적인 앞뒤 표시 순서를 정하며 목록의 위쪽을 화면 앞쪽으로 표시한다.
- 카드를 선택하면 사이드바의 선택한 펫 설정 전체가 같은 `instanceID`를 편집한다.
- 같은 설치 펫을 다시 추가할 때는 기존 설정 복사 또는 기본 설정 시작을 선택한다.
- 성능 경고는 카드 목록 위에 한 번만 표시하고 각 카드에 중복 경고를 쌓지 않는다.
- 펫이 하나뿐인 사용자는 현재와 같은 간단한 사용 흐름을 유지하며 인스턴스·프로필 같은 기술 용어를 UI에 노출하지 않는다.

### 플랫폼 표현

- macOS는 `NavigationSplitView` 또는 동등한 sidebar settings shell과 SwiftUI detail 화면을 사용한다.
- Windows는 WinUI `NavigationView`와 같은 그룹·명칭을 사용하되 Windows 네이티브 간격과 명령 배치를 따른다.
- macOS 상태 메뉴와 Windows notification area는 `모든 펫` 명령 뒤에 펫별 하위 메뉴를 제공한다.

## 검증 방법

- schema-v10의 내장·설치 펫, 표시 상태, 좌표, 프로필과 모션 참조가 v11 첫 인스턴스로 무손실 이관되는지 확인한다.
- 같은 설치 펫을 여러 번 활성화해도 instance ID, 창, 위치와 런타임 상태가 충돌하지 않는지 확인한다.
- 같은 원본 펫의 한 인스턴스에서 행동·이동·말풍선 설정을 바꿔도 다른 인스턴스가 바뀌지 않고, 원본 정의 편집 시 해당 인스턴스만 새 편집 사본으로 전환되는지 확인한다.
- 한 인스턴스의 드래그·재우기·설정 변경·삭제가 다른 인스턴스의 위치와 실행 상태를 바꾸지 않는지 확인한다.

## 남은 위험 / 후속 작업

- macOS와 Windows의 마케팅 버전은 `1.1.0`으로 통일하되 빌드 번호는 플랫폼별 기존 배포 이력을 보존해 각각 결정해야 한다.
- 제품상 마릿수 제한을 없애더라도 설정 파일과 창 생성의 방어 경계를 완전히 제거하면 손상 파일이 앱 시작을 막을 수 있으므로 안전 상한의 성격과 사용자 안내를 구분해야 한다.

- 완전히 멈춘 프로세스는 자체 경고나 메뉴에 응답할 수 없으므로 별도 감시 프로세스를 두지 않는 첫 구현에서는 강제 종료 후 안전 시작이 최종 복구 경계다.
- macOS에서 Windows portable 계층을 작업하려면 .NET SDK 10.0.302를 별도로 설치해야 한다. Windows UI·오버레이·배포 검증은 Windows PC에서만 완료할 수 있다.
- 필수 장시간 성능 검증은 플랫폼별 Release 대표 workload를 5분 측정한다. 1시간 soak와 장시간 GPU·프레임 지연은 공개 배포 전 또는 5분 표본에서 누수 징후가 있을 때 선택적으로 확장한다.
