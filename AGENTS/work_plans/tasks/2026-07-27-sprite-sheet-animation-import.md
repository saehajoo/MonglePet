# 스프라이트 시트 애니메이션 가져오기

## 상태

- 상태: in_progress
- 생성일: 2026-07-27
- 마지막 갱신: 2026-07-28

## 목표

- 사용자가 정적 PNG 또는 WebP 스프라이트 시트 한 장을 선택해 여러 애니메이션 프레임으로 가져올 수 있게 한다.
- 앱이 1차 프레임 경계를 제안하되 사용자가 포함할 프레임과 격자 구성을 최종 결정하게 한다.
- 단색 배경 제거는 비파괴 미리보기와 명시적 선택으로만 적용한다.
- 가져온 프레임을 기존 사용자 펫 생성·애니메이션 추가·애니메이션 수정 흐름과 동일하게 편집하고 저장한다.

## 범위

- 정적 PNG·정적 WebP 한 장 디코딩과 형식·크기·프레임 수 검증
- 알파 또는 모서리 배경색을 이용한 프레임 경계 1차 제안
- 균등 행·열 격자 재구성과 프레임 선택·해제·순서 확정
- 선택적 단색 배경 제거, 배경색과 허용 범위 조절 및 결과 미리보기
- 선택 프레임을 메모리 이미지로 기존 공통 캔버스 편집기에 전달
- 새 펫 만들기, 애니메이션 추가와 기존 애니메이션 수정 화면 연결
- 범용 AI 스프라이트 제작 프롬프트 복사
- 도메인 단위 테스트, 전체 XCTest와 Debug 빌드

## 제외 범위

- animated WebP 시간축 직접 재생
- 앱 안에서 OpenAI 또는 다른 이미지 생성 API 직접 호출
- AI가 만든 캐릭터의 저작권 또는 라이선스 적법성 자동 판정
- 자유형 다각형 마스킹과 전문 이미지 편집 기능
- 원본 스프라이트 시트와 편집 경계 메타데이터의 `.monglepet` 저장
- 저장 atlas의 WebP 재인코딩

## 열린 질문

- 없음

## 결정사항

- WebP는 애니메이션 파일이 아니라 정적 스프라이트 시트 입력으로만 받는다.
- 자동 탐지 결과는 제안일 뿐이며 선택되지 않은 경계는 저장하지 않는다.
- 자동 탐지가 만족스럽지 않으면 사용자가 행·열 수를 지정한 균등 격자로 즉시 바꿀 수 있게 한다.
- 배경 제거는 기본적으로 끄고, 모서리에서 추정한 후보색과 허용 범위를 사용자가 확인한 뒤 켠다.
- 원본 이미지는 변경하지 않으며 확정된 프레임만 메모리에서 잘라 기존 PNG atlas 작성기로 전달한다.
- 결과 패키지는 현재와 같이 투명 PNG atlas를 단일 원본으로 저장한다.
- 제품 UI에서는 Codex 전용 명칭 대신 `스프라이트 시트`와 `AI 제작 프롬프트`라는 범용 명칭을 사용한다.

## 검증 방법

- 투명 PNG, 불투명 단색 배경 PNG와 정적 WebP에서 예상 프레임 경계를 제안하는지 확인한다.
- animated WebP, 손상 파일, 확장자·실제 형식 불일치와 제한 초과 이미지를 거부하는지 확인한다.
- 균등 격자의 행·열, 선택 상태와 읽기 순서가 확정 프레임에 반영되는지 확인한다.
- 배경 제거를 끄면 원본 픽셀이 유지되고 켜면 선택 색상 범위만 투명해지는지 확인한다.
- 새 펫, 애니메이션 추가와 수정 결과가 기존 PNG 프레임과 함께 저장·재생되는지 확인한다.
- 가장 좁은 관련 테스트 후 전체 `MonglePetTests`와 Debug 빌드를 실행한다.
- XCUITest는 Codex 활성 세션 충돌 기록에 따라 컴파일만 확인하고 실제 화면 흐름은 Xcode 수동 QA로 확인한다.

## 완료 결과

- 정적 PNG·WebP 스프라이트 시트에서 자동 경계 제안, 선택·제외, 균등 격자, 선택적 배경 제거와 프레임 저장 흐름을 제공한다.
- 새 펫 만들기, 애니메이션 추가와 수정이 분할 프레임을 기존 공통 캔버스 편집과 PNG atlas 저장 경계로 전달한다.
- 자동 경계가 규칙적인 원본 셀을 보존하고 투명 입력에는 추가 배경 제거를 적용하지 않으며, 사용자가 overlay의 픽셀 아트 보간을 선택할 수 있다.
- 1차 자동·수동 검증과 실제 세로형 WebP 수동 QA를 완료했다.

- 저장 자산을 WebP로 다시 인코딩하는 최적화는 패키지 크기와 화질 측정 후 별도로 결정한다.
- 원본 셀 보존과 픽셀 아트 표시 보완을 완료한 뒤 같은 1536×1872 WebP로 저장 atlas와 실제 overlay를 다시 비교한다.
