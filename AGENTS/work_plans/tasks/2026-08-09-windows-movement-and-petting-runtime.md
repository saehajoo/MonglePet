# Windows 이동·드래그·쓰다듬기 런타임

## 상태

- 상태: completed
- 생성일: 2026-08-09
- 마지막 갱신: 2026-08-09

## 목표

- Windows에서 펫별 `fixed`, `cursorFollowing`, `freeRoaming`, `cursorAvoiding` 설정을 실제 오버레이 이동에 연결한다.
- 다중 모니터 작업 영역과 음수 가상 데스크톱 좌표에서 펫이 화면 밖으로 벗어나지 않게 한다.
- 클릭 통과가 꺼진 펫을 사용자가 직접 드래그하고 위치를 저장하며, 자동 이동보다 사용자 입력을 우선한다.
- 현재 프레임 위 호버 쓰다듬기를 일회성 모션으로 재생하고 진행 중 행동 또는 이동 표시로 복귀한다.

## 범위

- Windows 전용 순수 이동 좌표·상태 모델과 단위 테스트
- 포인터 위치·모니터 작업 영역 adapter
- 33ms 이동 tick, 비활성·정지 상태 저빈도 polling과 자유 이동 dwell
- 네 이동 모드와 전역 이동 범위 적용
- 실제 적용 좌표 기반 방향 모션 선택과 일반 행동 표시 복귀
- Win32 overlay 드래그 입력과 완료 위치 저장
- 300ms 호버 쓰다듬기, 동일 호버 1회, 이탈 뒤 재활성화와 도망가기 모드 차단
- 이동·쓰다듬기 설정 WinUI와 즉시 저장·실행 반영
- Debug·Release 자동 검증과 packaged Release 실제 QA

## 제외 범위

- 전면 앱 대표 창 근처 자유 이동의 정밀 창 선택
- 현재 프레임 알파 마스크 기반 투명 픽셀 제외
- 사용자 지정 이동 영역을 화면에서 직접 그리는 편집기
- 말풍선과 마우스 겹침 투명화
- 이동 물리, 충돌, 중력과 여러 펫 동시 이동

- 없음

## 결정사항

- Windows 화면 좌표는 Win32 가상 데스크톱의 좌상단 원점 좌표를 그대로 사용하고 macOS 좌표 변환 코드를 공유하지 않는다.
- 자동 이동 좌표는 지속 저장하지 않으며 사용자 드래그 완료와 명시적인 현재 화면 이동만 overlay 위치를 저장한다.
- 이동 runtime은 설정창과 분리해 notification area 상태에서도 계속 실행하고 재우기·잠금·절전·드래그 중에는 즉시 멈춘다.
- 실제 적용된 overlay 좌표 차이로 방향을 계산하고 선택된 모션이 없으면 현재 행동을 계속 표시한다.
- 쓰다듬기는 포인터의 패널 진입과 300ms 체류로 시작하며 클릭 자체는 입력으로 사용하지 않는다. 알파 마스크 판정은 후속 보강으로 남긴다.
- 자유 이동의 전면 앱 선호 설정은 보존하되 Windows 대표 창 provider가 추가되기 전에는 허용 작업 영역 안 무작위 목표로 안전하게 대체한다.

## 검증 방법

- 좌·우·상·하·음수 좌표 화면의 safe bounds, 목표 clamp, 속도·경과 시간·정지 반경 advance를 단위 테스트한다.
- 마우스 따라가기 목표 거리, 자유 이동 결정 샘플, 도망 거리·해제 히스테리시스와 이동 범위를 단위 테스트한다.
- 실제 적용 좌표 방향 분류, 방향 모션 fallback과 호버 300ms·이탈 재활성화를 단위 테스트한다.
- packaged Release에서 네 이동 모드, 다중 모니터 왕복, 드래그 저장·재실행, 클릭 통과와 쓰다듬기, 숨김·잠금 pause를 확인한다.
- 비활성·위치 고정 상태 timer, 충돌 이벤트, 설정 임시 파일과 CPU 기준을 확인한다.

## 진행 로그

- 2026-08-09: macOS 기준 동작과 Windows schema-v10 이동·쓰다듬기 Domain, overlay·행동 runtime 경계를 대조하고 저장 schema 변경 없는 연결 범위를 확정했다.
- 2026-08-09: WinUI·Win32 비의존 이동 Geometry에 safe bounds, 목표 clamp, 마우스 따라가기·자유 이동·도망 목표, 속도 advance, Windows 좌표 방향 분류와 호버 상태 모델을 구현했다.
- 2026-08-09: `PetMovementRuntime`을 추가해 네 이동 모드, 전역 이동 범위, 33ms 이동 tick·정지 100ms polling, 자유 이동 dwell과 도망 release 거리를 실제 overlay에 연결했다.
- 2026-08-09: overlay의 `HTCAPTION` 드래그와 enter/exit move 생명주기, 완료 위치 저장, 화면 구성 변경 clamp를 연결했다. 자동 이동 좌표는 LocalState에 저장하지 않는다.
- 2026-08-09: 이동 모션은 행동 시간축을 유지한 표시 override로, 호버 쓰다듬기는 행동 시간축을 멈춘 일회성 override로 연결하고 완료 뒤 최신 이동 또는 행동 모션으로 복귀하게 했다.
- 2026-08-09: WinUI에 이동 모드·속도·거리·정지 반경·자유 이동 dwell·도망 설정·이동 범위·fallback 모션·쓰다듬기 모션 편집을 추가했다.
- 2026-08-09: x64 Debug·Release 전체 빌드와 Activity 21개·Core 27개·Packages 18개·PetLibrary 10개·Settings 37개·Shell 8개, 총 121개 xUnit 테스트가 모두 통과했다.
- 2026-08-09: 실제 packaged Release에서 마우스 따라가기, 자유 이동, 도망가기, 드래그 hit-test·위치 저장·재실행 복원, 호버 쓰다듬기·행동 복귀를 확인했다. 선택 DISPLAY1 자유 이동은 DISPLAY2의 양수 좌표에서 음수 좌표 `-1589, 447`까지 진입했다.
- 2026-08-09: 자유 이동 중 WTS 잠금 메시지 뒤 좌표가 `743, 652`에서 1초 이상 유지되고 해제 뒤 `44, 23`으로 이동을 재개해 세션 생명주기 pause/resume을 확인했다.
- 2026-08-09: 위치 고정·쓰다듬기 미지정 상태 10초 측정은 전체 시스템 환산 CPU 0.182%, private memory 134.2MiB였다. QA 설정은 기존 값으로 복원하고 앱을 명시적으로 종료했다.
- 2026-08-09: UI Automation이 이동 모드 ComboBox popup을 열린 채 종료한 비사용자 경로에서 `Microsoft.UI.Xaml.dll` 접근 위반을 재현했다. 이동 tick의 화면 갱신 적체를 제거하고 종료 전에 Page timer·event 구독을 해제했으며 notification area command를 native callback 밖의 UI queue에서 처리하도록 보강했다.
- 2026-08-09: 실제 선택처럼 ComboBox popup을 닫은 이동 모드·속도 변경 직후 종료 3회와 설정 복원 종료 1회에서 새 충돌 이벤트 0개를 확인했다. 설정 변경 없는 명시적 종료도 새 충돌 이벤트 0개였고 QA 설정은 위치 고정·속도 160으로 복원했다.

## 완료 결과

- Windows schema-v10의 기존 이동·쓰다듬기 필드를 변경 없이 실제 Composition overlay와 WinUI 설정에 연결했다.
- 위치 고정, 마우스 따라가기, 자유 이동과 마우스 도망가기가 음수 좌표 듀얼 모니터 작업 영역 안에서 동작한다.
- 클릭 통과가 꺼진 overlay는 전체 펫 영역을 비활성 `HTCAPTION`으로 제공해 드래그할 수 있고, 완료 위치만 화면 식별자와 함께 저장·복원한다.
- 300ms 포인터 주도 호버는 한 번만 쓰다듬기 모션을 재생하며 이탈 후 재활성화되고, 도망가기 모드와 사용자 드래그 중에는 차단된다.
- 이동 모션은 행동 진행을 바꾸지 않고 쓰다듬기는 중단한 행동 시간축을 보존하며, 둘 다 누락 모션에서 현재 행동 표시를 유지한다.
- x64 MSIX `MonglePet.Windows_1.0.0.0_x64.msix`를 생성했다. `mspdbcmf.exe` 부재로 심볼 패키지만 생성되지 않는 경고 1개가 남는다.
