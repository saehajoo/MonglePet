# 펫 라이선스 메타데이터 제거

## 상태

- 상태: done
- 생성일: 2026-08-07
- 마지막 갱신: 2026-08-07

## 목표

- 펫 만들기·정보 수정·가져오기·내보내기에서 펫 라이선스 입력과 표시를 제거한다.
- 문자열 비교에 의존한 공유 차단 정책을 제거하고 사용자 제작과 편집 가능한 사본의 자유도를 유지한다.
- 기존 `license` 필드가 있는 `.monglepet`은 계속 가져올 수 있지만 새 패키지에는 해당 필드를 기록하지 않는다.
- 별도 웹 커뮤니티가 같은 정책과 식별자 경계를 구현할 수 있는 인계 프롬프트를 제공한다.

## 범위

- schema-v1 `pet.json`의 `license`를 읽기 전용 레거시 선택 필드로 전환
- macOS 펫 생성·편집 요청과 설정 UI에서 라이선스 제거
- 로컬 공유 검토의 라이선스 차단·표시·변경 재확인 제거
- 패키지 명세, 제품·아키텍처·테스트·결정과 웹 인계 문서 동기화
- 관련 XCTest 갱신과 Debug 빌드 검증

## 제외 범위

- 저장소의 PolyForm Noncommercial 소스 라이선스 제거 또는 변경
- ZIPFoundation 등 제3자 고지 변경
- 파일을 외부 도구로 수정하지 못하게 하는 DRM·암호화·패키지 서명
- 웹 커뮤니티 자체 구현

## 열린 질문

- 없음

## 결정사항

- 가져온 원본은 계속 읽기 전용으로 보호하고 사용자는 언제든 새 package ID의 편집 가능한 사본을 만들 수 있다.
- 펫 라이선스와 편집 가능 여부를 연결하지 않는다.
- 기존 manifest의 `license`는 디코딩 호환만 제공하고 Domain metadata, UI, 새 내보내기와 웹 metadata에서 사용하지 않는다.
- 웹의 게시 권한은 라이선스 문자열 판별 대신 로그인한 업로더의 게시 권한 확인, 신고·삭제 절차와 관리자 검토로 관리한다.

## 검증 방법

- `license`가 없는 새 schema-v1 manifest를 로더가 읽고 내보내기 왕복에서도 생략하는지 확인한다.
- 기존 `license` 문자열이 있는 fixture와 외부 패키지는 계속 가져올 수 있는지 확인한다.
- 펫 만들기·정보 수정·가져오기·내보내기 화면에 라이선스 입력이나 표시가 남지 않는지 확인한다.
- 공유 검토가 이름·버전·제작자 snapshot 변경은 재확인하되 라이선스 문자열로 차단하지 않는지 확인한다.
- 관련 XCTest, 전체 `MonglePetTests`와 Debug 빌드를 실행한다.

## 완료 결과

- 새로 만드는 펫과 다시 내보내는 `.monglepet`은 `license`를 기록하지 않는다.
- 기존 `license` 포함 패키지와 필드가 없는 패키지는 동일하게 로드되며 해당 값은 앱 정책에 영향을 주지 않는다.
- 읽기 전용으로 가져온 원본은 보호하면서 새 package ID의 편집 가능한 사본을 만들 수 있다.
- 공유 전에는 제작자·버전 등 현재 정보와 게시 권한을 확인하고 라이선스 문자열로 공유를 차단하지 않는다.
- 웹 커뮤니티 서버 구현자가 그대로 사용할 수 있는 전달 프롬프트를 추가했다.

## 남은 위험 / 후속 작업

- 기존 외부 도구가 `license`를 필수로 가정한다면 갱신된 schema와 fixture를 전달해야 한다.
- 웹 커뮤니티는 패키지 ID를 소유권 근거로 신뢰하지 않고 서버 Pet UUID와 인증된 소유자 관계를 사용해야 한다.
