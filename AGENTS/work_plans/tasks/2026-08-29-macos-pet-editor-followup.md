# macOS 펫 제작기·활성 인스턴스 후속 동등성

## 상태

- 상태: in_progress
- 생성일: 2026-08-29
- 마지막 갱신: 2026-08-29

## 목표

- Windows 1.4.0 Preview 2에서 확정한 제작 버전, 새 펫·사본 활성화와 설정 화면 안정성 결과를 macOS 네이티브 구조에 반영한다.
- 랜덤 행동 중 이동이 시작되면 현재 랜덤 행동을 중단하고 shuffle bag의 다음 행동을 준비해, 이동 종료 시 첫 프레임·첫 cycle부터 자연스럽게 시작한다.

## 범위

- 앱 제작 UI와 `UserPetPackageEditor`의 ASCII `MAJOR.MINOR.PATCH` 검증
- 외부·레거시 패키지 자유 문자열 버전 읽기 호환 유지
- 새 펫과 편집 가능한 사본의 새 설치·활성 인스턴스·독립 프로필 생성
- 설치 성공 뒤 설정 저장 실패까지 포함한 rollback
- 기존 설치 UUID를 유지하는 정보·애니메이션 편집 경계 보존
- 이동 표시와 랜덤 행동 shuffle bag 전환, 자동·직접 행동 복원 회귀 검증
- 설정 화면의 고빈도 런타임 구독 점검과 입력 상태 유지 QA

## 제외 범위

- 패키지 `formatVersion`, 앱 설정 schema와 권장 프로필 schema 변경
- Windows HWND 입력 통과·WinUI 테마 구현의 macOS 이식
- 편집 이력 저장, 앱 버전·빌드 번호 승격과 GitHub Release

## 열린 질문

- 없음. 랜덤 모드는 이동 시작 시 현재 행동을 버리고 다음 shuffle bag 항목을 준비하는 Windows 사용자 결과로 확정했다.

## 결정사항

- 앱이 새로 기록하는 펫 콘텐츠 버전만 ASCII 숫자 세 구성 요소의 `MAJOR.MINOR.PATCH`로 제한하고 외부 loader는 비어 있지 않은 자유 문자열을 계속 허용한다.
- 사본 설정 원본은 선택한 원본 펫의 현재 선택 인스턴스를 우선하고, 없으면 같은 펫의 표시 순서가 가장 앞선 활성 인스턴스를 사용한다. 활성 원본이 없으면 다른 펫 설정을 복사하지 않고 새 펫 기본 프로필을 사용한다.
- 신규 설치는 settings 저장 성공 전 활성 런타임에 publish하지 않는다. 설정 저장 실패 시 신규 설치를 제거하고 이전 메모리 설정과 선택을 유지한다.
- 안전 시작·전체 일시정지 같은 저빈도 제어는 유지하고 좌표·프레임·이동 tick 같은 고빈도 상태를 설정 루트가 구독하지 않게 한다.

## 진행 로그

- 2026-08-29: Windows Preview 2 소스와 D-104·D-105, macOS 인계 및 현재 코드를 대조했다. Windows 랜덤 이동 결과와 로컬 D-106의 pause/resume 결정이 충돌함을 확인하고 사용자 승인으로 Windows의 다음 shuffle bag 행동 재시작을 기준으로 확정했다.
- 2026-08-29: 앱 제작 버전 validator와 필드 인접 안내, 새 설치 settings 선저장 transaction, 새 인스턴스·프로필 생성과 교차 펫 키 사본 복사를 구현했다. 저장 실패 시 설치 제거·이전 선택 복원, 제거 실패 시 비활성 설치 복구 안내를 fault injection으로 검증했다.
- 2026-08-29: 이동 표시 시작을 상호작용 표시와 분리해 감지하고 랜덤은 다음 bag 행동을 첫 cycle로 restart했다. 자동·직접 행동의 경과 프레임 복원과 쓰다듬기 우선순위는 유지했다.
- 2026-08-29: 설정 화면은 저장 설정과 저빈도 전체 일시정지·안전 복구·자원 경고만 관찰하며 좌표·프레임·이동 tick·행동 진단 구독이 없음을 확인했다. 최종 전체 단위 테스트 514개 중 513개 성공·선택형 WebP fixture 1개 건너뜀·실패 0개와 코드서명 없는 Debug 빌드를 통과했다. 격리 UI 테스트는 두 번 모두 테스트 코드 실행 전 Runner bootstrap이 signal kill로 종료됐다. 대신 격리 Debug 앱의 자유 이동 2펫 5초 실행·정상 종료 smoke QA를 통과했으며 편집 흐름 수동 QA는 남겼다.

## 남은 위험 / 후속 작업

- macOS와 Windows 실제 패키지 교차 왕복은 두 운영체제 환경이 모두 필요하다.
- 현재 호스트의 `MonglePetUITests-Runner`가 bootstrap 전에 signal kill되어 UI 자동화가 실행되지 않았다. Xcode UI 테스트 실행 환경을 복구하거나 사용자 수동 QA로 확인해야 한다.
