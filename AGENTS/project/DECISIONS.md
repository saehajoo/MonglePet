# MonglePet 결정 기록

프로젝트 전체에 영향을 주는 확정된 제품 및 기술 결정을 기록한다. 결정이 바뀌면 기존 항목을 지우지 않고 상태와 대체 결정을 남긴다.

## D-001 독립 코드베이스

- 상태: accepted
- 결정일: 2026-07-21
- 결정: `bssm-oss/desktop-pet`과 유사 제품은 기능 및 UX 참고 자료로만 사용하고 포크하거나 소스 구조를 복사하지 않는다.
- 이유: MonglePet의 제품 규칙, 펫 패키지, 성능 및 개인정보 기준에 맞는 독립적인 구조가 필요하다.

## D-002 macOS 우선 네이티브 구현

- 상태: accepted
- 결정일: 2026-07-21
- 결정: 초기 버전은 macOS 14 이상, Swift 6, AppKit, SwiftUI, Core Animation으로 구현한다.
- 이유: 투명 오버레이, 시스템 이벤트, 저전력 애니메이션을 macOS 기본 기술로 제어하기 적합하다.

## D-003 파일 기반 로컬 저장소

- 상태: accepted
- 결정일: 2026-07-21
- 결정: Xcode 프로젝트 생성 시 Storage는 `None`을 선택하고, 앱 설정은 버전이 지정된 JSON, 펫 라이브러리는 파일 시스템으로 저장한다.
- 이유: MVP 데이터는 관계형 객체 그래프보다 설정 스키마와 패키지 파일에 가깝고 향후 Windows 구현과 스키마를 공유하기 쉽다.

## D-004 개인정보 최소 처리

- 상태: accepted
- 결정일: 2026-07-21
- 결정: 전면 앱 bundle identifier, 입력 후 경과 시간, 화면 잠금 및 절전 상태만 로컬에서 처리한다. 실제 키 입력, 창 제목, 문서명, 브라우저 주소, 화면 내용은 읽거나 저장하지 않는다.
- 이유: 자동 행동에 필요한 정보만 사용하면서 별도 접근성 권한과 개인정보 위험을 최소화한다.

## D-005 데이터 전용 펫 패키지

- 상태: accepted
- 결정일: 2026-07-21
- 결정: `.monglepet` 패키지에는 JSON과 이미지 데이터만 허용하고 실행 코드, 스크립트, 플러그인을 허용하지 않는다.
- 이유: 외부 펫 등록 기능의 보안성과 이식성을 확보한다.

## D-006 Windows 별도 구현

- 상태: accepted
- 결정일: 2026-07-21
- 결정: macOS 버전이 안정화된 뒤 Windows UI, 시스템 감지, 렌더러를 별도 네이티브 앱으로 구현한다. 데이터 스키마와 테스트 시나리오만 공유한다.
- 이유: 플랫폼별 창 관리와 시스템 API 차이를 억지로 공통화하지 않기 위해서다.

## D-007 앱 식별자

- 상태: accepted
- 결정일: 2026-07-21
- 결정: 앱 Bundle Identifier는 `kr.mapleroom.MonglePet`을 사용한다.

## D-008 메뉴 막대 중심 앱

- 상태: accepted
- 결정일: 2026-07-21
- 결정: MonglePet은 Dock 아이콘이 없는 메뉴 막대 중심 앱으로 구성한다. AppKit `NSStatusItem`을 기본 진입점으로 사용하고 설정창은 필요할 때만 연다.
- 이유: 펫 창을 닫거나 숨긴 상태에서도 깨우기, 설정과 앱 종료 기능에 항상 접근할 수 있어야 한다.

## D-009 펫 오버레이 창

- 상태: accepted
- 결정일: 2026-07-21
- 결정: 펫은 투명하고 테두리가 없는 non-activating `NSPanel`에 표시한다. 패널은 일반 앱 위와 모든 Space 및 전체 화면 보조 공간에 표시하되 화면 보호기나 화면 잠금보다 위에 표시하지 않는다.
- 이유: 사용자의 현재 작업을 활성화 해제하지 않으면서 데스크톱 펫을 지속적으로 보여주기 위해서다.

## D-010 1단계 임시 펫 자산

- 상태: accepted
- 결정일: 2026-07-21
- 결정: 1단계 오버레이 검증에는 투명 배경의 교체 가능한 정적 PNG 한 장을 사용한다. 정식 WebP 아틀라스와 모션 재생은 2단계에서 구현한다.
- 이유: 창 생명주기와 상호작용을 애니메이션 및 패키지 로더와 분리해 먼저 검증하기 위해서다.

## D-011 Codex WebP 아틀라스 가져오기

- 상태: accepted
- 결정일: 2026-07-21
- 결정: Codex legacy v1 8×9 WebP 아틀라스와 v2 8×11 WebP 아틀라스를 가져오기 형식으로 지원한다. 가져온 데이터는 MonglePet 내부 manifest로 변환하며 Codex 고정 행 구조를 내부 런타임 모델로 직접 사용하지 않는다.
- 이유: 기존 Codex 펫 자산과의 호환성을 제공하면서 MonglePet의 모션 및 패키지 규격을 독립적으로 유지하기 위해서다.
- 비고: animated WebP 단일 파일 재생은 이 결정의 범위가 아니며 MVP 가져오기 대상에서 제외한다.

## D-012 1단계 표시 상태와 위치 복구

- 상태: accepted
- 결정일: 2026-07-21
- 결정: 1단계의 재우기는 펫 패널을 파기하지 않고 숨기며, 깨우면 실행 중 마지막 위치를 사용한다. 디스플레이 구성이 변경되어 패널이 화면 밖에 있으면 가장 많이 겹치는 사용 가능 화면 안으로 보정하고, 어느 화면과도 겹치지 않으면 주 화면으로 복구한다.
- 이유: 숨긴 펫을 즉시 복구하면서 디스플레이 분리 후 조작할 수 없는 위치에 남는 상황을 방지하기 위해서다. 앱 재실행 후 위치 영구 복원은 5단계 설정 저장 범위에서 다룬다.

## D-013 ZIP 패키지 해제

- 상태: accepted
- 결정일: 2026-07-21
- 결정: ZIPFoundation 0.9.20을 Swift Package로 정확히 고정해 사용한다. 패키지 전체 해제 편의 API에만 의존하지 않고 모든 엔트리의 경로, 종류, 중복, 크기와 압축률을 먼저 검사하며 심볼릭 링크를 거부한 뒤 개별 추출한다.
- 이유: App Sandbox 안에서 외부 프로세스 없이 ZIP을 처리하면서 zip-slip, 심볼릭 링크 탈출과 압축 폭탄을 MonglePet 규칙으로 방어하기 위해서다.
- 비고: ZIPFoundation의 MIT 라이선스 고지는 공개 배포 준비 시 포함한다.

## D-014 호환 입력의 내부 패키지 변환

- 상태: accepted
- 결정일: 2026-07-21
- 결정: Codex v1/v2, GIF, APNG와 PNG 시퀀스는 런타임에서 별도 형식으로 직접 재생하지 않고 임시 스키마 버전 1 `.monglepet` 디렉터리로 변환한 뒤 기존 `PetPackageLoader`로 다시 검증한다.
- 이유: 호환 형식별 파싱을 설치 및 재생 경계와 분리하고, 모든 가져온 펫에 동일한 보안 제한과 런타임 모델을 적용하기 위해서다.
- 비고: Codex 원본 atlas는 변경하지 않고 복사하며, GIF/APNG/PNG 시퀀스는 투명 PNG atlas의 반복 `idle` 모션 하나로 정규화한다.

## D-015 행동 전환 경계와 규칙 순서

- 상태: partially superseded by D-022 and D-024
- 결정일: 2026-07-22
- 결정: 일반 행동 목록 변경은 현재 `BehaviorStep`의 `duration`이 끝나는 단계 경계에서 적용하고, 일회성 상호작용만 즉시 시작한다. 자동 규칙은 종류별 결정 우선순위를 먼저 적용한 뒤 큰 `priority` 값부터 평가하며 같은 값은 설정 배열 순서를 유지한다.
- 이유: 짧은 입력 변화로 모션이 중간에 끊기거나 반복 전환되는 현상을 막으면서 사용자가 요청한 상호작용에는 즉시 반응하기 위해서다.
- 비고: 10분 이상 유휴 규칙은 장시간 유휴로 분류해 앱 규칙보다 먼저, 10분 미만 유휴 규칙은 앱 규칙 다음에 평가한다.

## D-016 macOS 활동 감지 API와 주기

- 상태: accepted
- 결정일: 2026-07-22
- 결정: 전면 앱은 `NSWorkspace.didActivateApplicationNotification`, 유휴 시간은 `CGEventSource.secondsSinceLastEventType`, 전원·세션 상태는 공개된 `NSWorkspace` 알림으로 감지한다. 유휴 시간은 1초 간격으로만 확인하고 이벤트 상태 변경은 즉시 발행한다.
- 이유: 실제 키 입력이나 화면 내용을 읽지 않고 접근성·화면 기록·입력 모니터링 권한 없이 자동 행동에 필요한 최소 입력을 얻기 위해서다.
- 비고: 비공개 화면 잠금 분산 알림은 사용하지 않는다. 사용자 세션 비활성화 또는 화면 수면을 화면 사용 불가 상태로 보수적으로 합쳐 `ActivitySnapshot.isScreenLocked`로 전달하며, 해당 상태와 시스템 절전 중에는 polling 및 렌더링을 중지한다.

## D-017 설정 저장 검증과 미래 버전 보호

- 상태: accepted
- 결정일: 2026-07-22
- 결정: schema-v1 설정은 Domain과 저장 DTO를 분리하고 저장 시 전체 값을 엄격하게 검증한다. 로드 시에는 잘못된 항목만 독립적으로 복구하며, 손상 파일은 격리하고 현재 앱보다 새로운 스키마 파일은 원본을 유지한 채 설정 쓰기를 차단한다.
- 이유: 일부 사용자 설정 오류 때문에 전체 구성을 잃지 않으면서도, 구버전 앱이 새로운 형식의 파일을 덮어써 데이터가 소실되는 일을 막기 위해서다.
- 비고: 설정 파일은 최대 5MiB, overlay 너비는 96–384pt, 재생 속도는 0.25–4.0, 행동 목록·목록별 단계·자동 규칙은 각각 최대 100개, 시간 값은 최대 24시간으로 제한한다. 로그인 시 실행은 JSON이 아니라 향후 `SMAppService` 상태를 원본으로 사용한다.

## D-018 설정 세션과 overlay 복원

- 상태: accepted
- 결정일: 2026-07-22
- 결정: `AppSettingsSession`을 저장소와 UI·`AppCoordinator` 사이의 단일 실행 상태로 사용한다. overlay는 디스플레이 UUID와 전역 좌표를 저장하고 현재 visible frame으로 보정하며, 드래그 완료 시 저장한다. 크기 조작은 즉시 반영하되 파일 저장은 조작 종료 시 수행한다.
- 이유: 파일 시스템 책임을 SwiftUI와 AppKit에서 분리하면서 연속 슬라이더 입력의 불필요한 디스크 쓰기를 줄이고, 디스플레이 분리 후에도 펫을 조작 가능한 위치로 복구하기 위해서다.
- 비고: 클릭 통과 상태에서도 메뉴 막대와 설정창을 복구 경로로 유지한다. 미래 스키마에서는 영구 편집을 막지만 실행 중 깨우기·재우기는 허용한다.

## D-019 기본 행동 프리셋과 런타임 timer

- 상태: superseded by D-022
- 결정일: 2026-07-22
- 결정: 행동 목록이 비어 있는 첫 실행·기존 설정에는 `idle`, `focus`, `rest`, `sleep` 3초 목록과 유휴 2분 `rest`, 10분 `sleep` 규칙을 메모리에서 주입한다. `PetBehaviorRuntime`은 현재 단계의 남은 시간에 맞춘 일회성 timer로 `BehaviorResolver`, `MotionScheduler`와 `FramePlayer`를 연결한다.
- 이유: 기존 schema-v1 파일을 깨지 않고 즉시 사용 가능한 자동·수동 동작을 제공하며, 상시 실행 앱에서 짧은 주기의 별도 polling을 추가하지 않기 위해서다.
- 비고: 기본 프리셋은 다음 사용자 설정 저장 시 함께 기록한다. 임시 단일 이미지는 source rect와 프레임 시간으로 상태를 구분하며, 정식 펫 자산은 같은 motion ID로 교체한다. `playbackSpeed`는 프레임 delay에만 적용한다.

## D-020 행동 루틴 편집과 펫 애니메이션 구분

- 상태: partially superseded by D-024
- 결정일: 2026-07-22
- 결정: 사용자 UI에서는 `BehaviorSequence`를 **행동 루틴**, `PetMotion`을 **펫 애니메이션**으로 구분한다. 행동 루틴은 현재 펫이 가진 애니메이션 단계만 순서대로 조합하며 다른 행동 루틴을 단계로 중첩하지 않는다.
- 이유: 재생 가능한 원본 애니메이션과 사용자가 구성하는 시간 기반 조합을 명확히 구분하고, 중첩 루틴의 순환 참조와 모호한 재생 의미를 방지하기 위해서다.
- 비고: 시스템 `기본` 루틴은 삭제할 수 없지만 편집할 수 있다. custom 루틴 삭제 시 이를 참조하는 자동 규칙을 함께 제거하고 수동 선택을 안전한 기본값으로 복구한다. 현재 펫에 없는 저장된 애니메이션 ID는 설정에서 소실하지 않고 표시하며 runtime에서 해당 펫의 선언된 기본 애니메이션으로 폴백한다.

## D-021 편집 가능한 사용자 펫과 PNG 애니메이션

- 상태: partially superseded by D-024, D-025 and D-027
- 결정일: 2026-07-22
- 결정: 앱에서 PNG 한 장 또는 여러 장으로 만든 펫은 `.monglepet` schema-v1 패키지로 저장하고 전용 JSON marker로 편집 가능 여부를 구분한다. PNG 한 장은 정지 애니메이션, 여러 장은 사용자가 확정한 순서의 프레임 애니메이션이며 크기가 다르면 가장 큰 투명 셀 중앙에 맞춘다.
- 이유: 사용자 등록 기능을 기존 패키지 검증·라이브러리·런타임과 공유하면서 외부 패키지 원본을 의도치 않게 변형하지 않고 안전하게 확장하기 위해서다.
- 비고: 사용자 펫의 프레임 간격과 반복은 펫 애니메이션 자체의 값이고, 행동 루틴의 유지 시간과 재생 속도는 별도 값이다. 애니메이션 추가는 임시 패키지를 검증한 뒤 같은 설치 UUID로 원자적 교체한다. 일반 가져오기는 외부 패키지의 편집 marker를 제거하므로 가져온 패키지는 현재 버전에서 읽기 전용이다.

## D-022 사용자 자유 행동 기본값

- 상태: partially superseded by D-086
- 결정일: 2026-07-22

## D-033 선택형 공유 권장 프로필

- 상태: accepted
- 결정일: 2026-07-23
- 결정: `.monglepet`은 펫 데이터와 분리된 선택적·버전 지정 공유 권장 프로필을 포함할 수 있다. 권장 프로필에는 행동의 자동·수동 모드, 수동 선택, 행동 루틴과 공유 가능한 이동 모드·설정을 넣고, 받는 사용자가 적용 여부를 선택한다.
- 이유: 제작자가 의도한 펫의 행동 경험까지 교환하면서도 받는 사용자의 기존 설정을 덮어쓰거나 개인 환경 정보가 무심코 공유되는 일을 막기 위해서다.
- 비고: 설치 UUID, 로컬 펫 키, 화면·창 좌표와 현재 앱 상태는 항상 제외한다. 자유 이동 대기 시간, 모드별 이동 애니메이션과 쓰다듬기 애니메이션은 펫 모션 참조를 재검증해 포함한다. 앱 bundle identifier가 들어 있는 자동 규칙은 기본 제외하고 내보내는 사용자가 목록을 검토해 별도로 선택한 경우에만 포함한다. 기존 설치 교체는 로컬 프로필을 기본 보존하며 초기 버전에는 부분 병합을 제공하지 않는다. 지원하지 않는 미래 schema나 의미상 손상된 선택 프로필은 적용하지 않고 펫만 설치하되, 실행 파일·안전하지 않은 경로·크기 초과 같은 패키지 보안 위반은 전체 가져오기를 거부한다.

## D-034 행동 위의 이동·상호작용 표시 계층

- 상태: accepted
- 결정일: 2026-07-23
- 결정: 행동 루틴의 시간 진행은 그대로 유지하고 실제 자동 이동 중에는 모드별 선택 애니메이션을 임시로 표시한다. 쓰다듬기는 현재 펫에서 사용자가 선택한 애니메이션을 한 번 재생하며 이동 표시보다 우선한다.
- 이유: 사용자 제작 펫에 특정 애니메이션 이름을 강제하지 않으면서 이동과 클릭 반응을 자유롭게 구성하고, 임시 표시가 자동·수동 행동 루틴의 단계 진행을 재시작시키지 않게 하기 위해서다.
- 비고: 이동 애니메이션이 미지정·누락이면 기존 행동을 계속 표시하고, 이동이 끝나면 현재까지 진행된 행동으로 돌아간다. 쓰다듬기 애니메이션이 미지정·누락이면 입력만 무시한다. 쓰다듬기 재생 중 추가 입력은 합치고 완료 뒤 500ms cooldown을 적용한다. 쓰다듬기의 클릭 입력 방식은 D-044가 대체한다.

## D-065 Windows 자동 규칙의 앱 식별자와 활동 감지

- 상태: accepted
- 날짜: 2026-08-09
- 결정: Windows 전면 앱 규칙은 packaged 앱의 소문자 `pfn:<package-family-name>` 또는 일반 Win32 앱의 소문자 `exe:<file-name>`을 로컬 식별자로 사용한다. 입력 없음 시간은 `GetLastInputInfo`를 1초 간격으로 확인하고, 세션 잠금·해제와 시스템 절전·복귀는 오버레이 HWND의 공개 WTS·전원 메시지로 감지한다.
- 이유: package family는 설치 위치가 바뀌어도 안정적이고, 일반 Win32 앱은 package identity가 없으므로 실행 파일명만 사용하는 것이 경로 저장 없이 자동 규칙 대상을 구분할 수 있는 최소 범위다. 1초 polling은 입력 없음 규칙의 최대 전환 지연과 상시 실행 CPU 비용 사이의 기존 제품 기준에 맞는다.
- 비고: 창 제목, 문서명, 브라우저 주소, 실제 입력 내용과 실행 파일 전체 경로는 snapshot·설정·로그에 저장하지 않는다. 앱 식별자는 Windows 로컬 설정에만 유지하고 권장 프로필이나 다른 플랫폼으로 내보내지 않는다. 숨김·잠금·절전 중에는 polling을 중지하고 복귀 시 즉시 새 snapshot을 발행한다.

## D-069 Windows 이동·드래그·쓰다듬기 실행 경계

- 상태: accepted
- 날짜: 2026-08-09

- 이유: 이동 규칙을 Win32 메시지와 UI에서 분리해 음수 좌표·다중 모니터·속도 경계를 결정적으로 테스트하고, 자유 이동이 사용자 위치 기록을 계속 덮어쓰지 않게 하기 위해서다. 전체 overlay를 비활성 caption으로 취급하면 설정창 포커스를 빼앗지 않고 네이티브 창 이동을 사용할 수 있다.

## D-093 행동 중심 사용자 모델과 자동 동작 우선순위

- 상태: accepted
- 날짜: 2026-08-26
- 결정: 애니메이션은 행동 단계의 프레임 자산으로 한정하고 자동·직접 선택, 이동 방향과 쓰다듬기는 안정적 ID와 변경 가능한 표시 이름을 가진 행동을 참조한다. 입력 없음 규칙은 프로필당 하나, 앱 규칙은 앱 식별자당 하나로 제한한다. 자동 동작 충돌은 `표시 및 이동`, `입력 없음 규칙`, `앱 사용 규칙` 세 항목을 사용자가 위에서 아래로 정렬한 순서로 결정한다. 로컬 설정은 schema-v12, 권장 프로필은 schema-v8로 올리고 구형 애니메이션 직접 참조는 중복 없는 한 단계 행동으로 승격한다.
- 이유: 같은 애니메이션을 여러 기능이 서로 다른 방식으로 직접 선택하는 혼동을 없애고, 애니메이션 이름을 바꿔도 기능 연결이 깨지지 않게 하며, 자동 규칙 행동과 실제 이동 중 어느 쪽을 적용할지 사용자가 직관적인 목록 순서로 선택할 수 있게 하기 위해서다.
- 비고: 쓰다듬기 일회성 행동은 항상 최상위다. 앱 또는 입력 없음 규칙이 `표시 및 이동`보다 위면 펫은 현재 위치에서 멈추고 해당 규칙의 행동을 표시한다. 규칙이 해제되면 현재 위치를 기준으로 이동을 다시 시작한다. `표시 및 이동`이 규칙보다 위면 이동 좌표와 이동 행동을 유지한다. 직접 선택 모드와 일치 규칙이 없는 자동 모드에서는 이동 행동이 직접·기본 행동보다 우선한다. 고빈도 이동 tick은 같은 행동 timer를 재시작하지 않는다. Windows는 별도 네이티브 구현과 실제 QA 후에만 동등 완료로 표시한다. 새 기본 펫과 Preview 릴리스는 사용자 자산 전달 뒤 별도 단계로 진행한다.

## D-101 이동 방식 독립 설정과 패키지 전체 옵션 공유

- 상태: accepted
- 날짜: 2026-08-26
- 결정: 로컬 설정을 schema-v14로 올려 `cursorFollowing`, `freeRoaming`, `cursorAvoiding`의 수치와 행동을 독립 저장한다. 도망가기의 평상시 자유 이동도 일반 자유 이동을 재사용하지 않고 `cursorAvoiding.idleFreeRoaming`에 속도·정지 반경·고정/랜덤 머무르기·전면 창 선호·행동을 별도로 둔다. 권장 프로필은 schema-v10으로 올리고 이 구조와 행동·규칙·쓰다듬기·말풍선 전체, 10~200% 펫 크기·클릭 통과·기본/겹침 투명도·픽셀 표시를 기록한다. 앱의 `패키지 파일로 저장`은 이 권장 프로필을 항상 포함하며 앱 규칙만 식별자 노출 때문에 별도 선택한다.
- 이유: 한 이동 방식의 시간 방식이나 수치를 편집했을 때 다른 방식의 설정이 바뀌는 문제를 없애고, 공유·내장 펫 교체 과정에서 제작자가 조정한 펫별 동작과 표시 옵션이 누락되지 않게 하기 위해서다.
- 비고: v13→v14와 권장 프로필 v9 이하는 종전 공용 값을 관련 이동 방식마다 복제해 최초 동작을 보존한다. v9 이하에는 표시 설정 자체가 없으므로 적용할 때 사용자의 현재 표시 옵션을 덮어쓰지 않는다. 새 v10 적용은 행동 프로필과 휴대 표시를 한 번의 settings 갱신으로 저장하면서 화면 좌표·디스플레이 식별자·모든 펫 공통 이동 범위·깨움·로그인 실행·설치/인스턴스 ID·사용 이력은 유지한다. Windows는 같은 JSON 의미와 이전 형식 호환·교차 왕복을 구현하고 실제 Windows QA 전까지 동등 완료로 표시하지 않는다.
