# macOS 펫 제작기 후속 인계

## 상태와 목적

- 상태: implementation_complete_qa_pending
- 작성일: 2026-08-29
- 기준: Windows 펫 제작기 UX 후속 보정과 D-104
- 목적: 사용자 요청에 따라 Windows에서 먼저 확정한 제작 UI 입력·활성 인스턴스 결과를 macOS 네이티브 구현에 반영한다.

이 문서는 Windows 코드를 Swift로 옮기기 위한 문서가 아니다. D-104의 공통 사용자 결과만 구현하고 macOS의 기존 SwiftUI 편집 캔버스·시트 구조를 유지한다.

## macOS에서 변경할 항목

### 제작 버전

- `UserPetEditorView`의 새 펫 버전과 `UserPetDetailsEditorView`의 수정 버전은 숫자형 `MAJOR.MINOR.PATCH`만 저장 가능하게 한다.
- 각 구성 요소는 ASCII 숫자만 사용하고 빈 구성 요소, 선행 0, 접두·접미사를 허용하지 않는다. 허용 예시는 `1.0.0`, 거부 예시는 `01.0.0`, `v1.0.0`, `1.0.0-beta`다.
- 저장 버튼 비활성화만으로 끝내지 말고 필드 가까이에 `버전은 1.0.0처럼 MAJOR.MINOR.PATCH 형식으로 입력해 주세요.`를 표시한다.
- `PetPackageLoader`의 기존 자유 문자열 읽기 계약은 바꾸지 않는다. 가져온 읽기 전용 펫과 과거 패키지는 계속 표시·설치한다.
- `UserPetPackageEditor.validatedDetails`는 앱 안에서 다시 기록하는 생성·수정 요청만 같은 규칙으로 검증한다.

### 새 펫과 편집 가능한 사본

- `PetLibrarySession.performUserPetChange`가 보관함 선택만 바꾼 뒤 기존 활성 인스턴스의 펫 키를 교체하는 흐름을 분리한다.
- 새 펫 생성 성공 시 새 설치 ID를 가리키는 활성 인스턴스와 기본 행동 프로필을 추가하고 선택한다. 기존 활성 인스턴스와 프로필은 보존한다.
- 편집 가능한 사본 생성 성공 시 새 설치·인스턴스·프로필 ID를 만들고 원본 활성 인스턴스의 행동·자동 동작·이동·쓰다듬기·말풍선과 overlay를 독립 복사한다. 원본은 활성 목록에 남긴다.
- 패키지 정보 수정과 애니메이션 추가·수정은 기존 설치 UUID를 원자적으로 교체하는 현재 경계를 유지하며 새 활성 인스턴스를 만들지 않는다.
- 생성 또는 사본 설치가 성공했지만 설정 저장이 실패하면 반쪽짜리 활성 참조가 남지 않도록 설치와 설정 변경의 복구 경계를 명시한다.

### 행동 전환과 설정 화면 안정성 확인

- 랜덤 행동 위에 이동 행동을 표시하면서 가려진 랜덤 행동을 계속 진행하지 않는다. 이동이 끝나면 shuffle bag의 다음 행동을 첫 프레임·첫 cycle부터 시작해 이전 행동의 끝부분이나 중간 프레임이 잠깐 보이지 않게 한다.
- 자동·직접 행동의 명시적인 중단·복원 의미는 유지하고, 위 규칙을 랜덤 행동 전환에만 적용한다.
- 설정 화면은 펫 좌표, 현재 프레임, 이동·행동 진단 같은 런타임 값을 계속 구독하지 않는다. 저장된 설정을 편집하는 화면으로 유지하고 펫 이동 때문에 텍스트 입력 포커스나 화면 구성이 갱신되지 않는지 확인한다.

## 이미 macOS 기준과 일치해 변경하지 않을 항목

- 애니메이션 미리보기 배율은 펫 content 크기에 적용하고 공통 캔버스 밖 배치를 허용한다.
- 스프라이트 읽기 순서는 경계 편집 중 자동 재정렬하지 않는다.
- 투명 격자와 버튼 계층은 macOS 네이티브 스타일을 유지한다.
- 패키지 schema와 편집 이력 필드는 추가하지 않고 최종 atlas 픽셀만 공유한다.
- Windows의 부모·자식 `HWND` 클릭 통과 복구와 WinUI 테마 리소스는 Windows 전용이므로 SwiftUI/AppKit에 옮기지 않는다.

## 권장 검증

- 새 펫을 만든 뒤 원래 활성 펫과 새 펫이 모두 목록·화면에 남는지 확인한다.
- 사본 생성 뒤 원본과 사본의 프로필·overlay를 각각 바꾸고 재실행해 독립성을 확인한다.
- 생성·정보 수정에서 정상·오류 버전 표본을 검증하고 외부 자유 문자열 패키지 가져오기는 계속 통과하는지 확인한다.
- 생성·사본 작업을 취소하거나 저장 실패를 유도했을 때 설치 폴더, 활성 인스턴스와 설정 파일이 부분 변경되지 않는지 확인한다.
- 랜덤 행동 중 이동을 시작하고 끝냈을 때 다음 랜덤 행동이 첫 프레임부터 시작하는지 확인한다.
- 펫을 계속 움직이는 동안 설정 텍스트 필드·스테퍼를 편집해 포커스와 입력값이 유지되는지 확인한다.

실제 macOS 구현·자동 테스트·앱 QA가 끝나기 전에는 `PLATFORM_PARITY.md`에서 D-104를 동등 완료로 표시하지 않는다.

## 2026-08-29 구현 결과

- 앱 제작·편집 버전은 공통 `UserPetContentVersion` validator와 필드 인접 안내를 사용한다. 외부 `PetPackageLoader`는 자유 문자열 버전을 계속 읽는다.
- 새 펫과 사본은 패키지 설치 뒤 설정 후보를 먼저 원자 저장하고 성공한 경우에만 새 인스턴스·프로필을 publish한다. 실패하면 신규 설치를 제거하고 이전 보관함 선택을 복원한다.
- 사본은 원본 펫의 선택 인스턴스 또는 표시 순서상 첫 활성 인스턴스를 원본으로 삼아 행동·규칙·이동·쓰다듬기·말풍선·overlay를 새 펫 키와 독립 UUID로 복사한다. 활성 원본이 없으면 다른 펫 설정을 복사하지 않는다.
- 랜덤 행동은 이동 시작 때 다음 shuffle bag 행동을 첫 cycle로 준비하고 이동 종료 뒤 첫 프레임부터 시작한다. 자동·직접 행동은 기존 경과 위치 복원을 유지한다.
- 설정 화면은 저장 설정과 저빈도 전체 일시정지·안전 복구·자원 경고만 관찰하며 좌표·현재 프레임·이동 tick·행동 진단 구독은 없다.
- 최종 전체 단위 테스트 514개 중 513개 성공·선택형 WebP fixture 1개 건너뜀·실패 0개와 코드서명 없는 Debug 빌드를 통과했다. 격리 Debug 앱의 자유 이동 2펫 5초 실행·정상 종료도 확인했다. 격리 UI 테스트는 Runner가 테스트 코드 실행 전 bootstrap에서 signal kill되어 실제 편집 UI QA와 Windows 교차 왕복은 남았다.
