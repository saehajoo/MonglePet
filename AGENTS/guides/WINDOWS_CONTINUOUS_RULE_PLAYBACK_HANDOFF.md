# Windows 조건 규칙 행동 연속 재생 인계

## 상태와 기준

- 기준일: 2026-09-08
- 공통 사용자 계약: D-135
- macOS: 구현·자동 검증 진행, 실제 앱 QA 대기
- Windows: `1.9.0.22`, `windows-v1.9.0-preview.1` 이후 후속 구현 대기

작업 전 루트 `AGENTS.md`, `apps/windows/AGENTS.md`, D-135, `BEHAVIOR_MODEL.md`와 `2026-09-08-continuous-rule-playback.md`를 읽는다. 기존 사용자 변경을 보존하고 Windows 환경에서만 Windows 소스·빌드·실제 QA를 진행한다.

## 확정 사용자 결과

- 앱 사용 규칙은 지정 앱이 전면에 있는 동안 선택 행동의 모든 단계와 단계별 반복 횟수를 소비한 뒤 첫 단계부터 다시 재생한다.
- 입력 없음 규칙은 유휴 시간이 임계값 이상인 동안 같은 방식으로 반복한다.
- 같은 활동 snapshot이나 같은 규칙 결정이 반복되어도 현재 단계·반복 횟수·사이클 경과를 초기화하지 않는다.
- 앱 전환·입력 재개로 조건이 해제되면 현재 사이클이 끝날 때까지 기다리지 않고 다음 규칙, 이동 또는 평상시 행동으로 즉시 전환한다. 실제 감지는 기존 1초 polling 범위 안에서 이뤄진다.
- 규칙이 이동보다 높으면 규칙 조건이 유지되는 동안 좌표 이동과 이동 행동을 멈추고 반복 규칙 행동을 표시한다. 이동이 규칙보다 높으면 기존처럼 이동 계층을 표시하며 가려진 규칙 scheduler를 진행시키지 않는다.
- 랜덤 후보가 비었거나 참조가 사라져 기본 행동으로 fallback하면 기본 행동을 계속 순환한다.

## 바꾸지 않는 문맥

- 평상시 `fixed`: 기존처럼 전체 행동 연속 순환
- 평상시 `random`: 각 행동 한 번 완료 후 shuffle bag의 다음 행동
- 쓰다듬기: 한 번 완료 후 중단한 결과로 복귀
- 이동 행동: 실제 좌표 이동 중에만 별도 반복
- 행동 대사: 같은 행동 ID의 반복 경계마다 다시 발생시키지 않음
- 저장 `repeats`, settings schema-v16, 제작자 설정 v12, package format, 규칙 우선순위와 활동 감지 주기

D-135는 D-111·D-115와 기존 `WINDOWS_MY_PETS_RUNTIME_POLISH_HANDOFF.md`의 “조건 규칙은 한 번 재생 후 마지막 프레임 유지” 부분만 대체한다. 그 문서의 내 펫·말풍선·랜덤·이동·저장 호환 계약은 유지한다.

## Windows 구현 방향

현재 Windows runtime은 규칙 전용 scheduler에 `MotionSequencePlayback.Once`를 전달한다. 규칙 계층에는 조건이 요청되는 동안 반복하는 playback 정책을 사용하도록 변경한다. 저장된 `BehaviorSequence.Repeats`를 읽어 결정하지 말고 `BehaviorSource.AutomaticRule` 문맥으로 선택한다.

1. `PetBehaviorRuntime`의 rule scheduler 요청을 `RepeatWhileRequested` 또는 동등한 문맥 정책으로 변경한다.
2. 동일 rule·sequence 요청은 scheduler cursor를 새로 만들지 않는다.
3. 해석된 행동 목록이나 같은 ID의 행동 내용이 바뀌면 첫 단계·첫 cycle에서 시작한다. 서로 다른 규칙이 완전히 같은 행동을 선택하면 같은 표시 문맥으로 보고 현재 위치를 유지해도 된다.
4. 규칙 해제 시 rule scheduler를 멈추고 base/movement 계층을 기존 우선순위대로 복구한다.
5. 이동이 표시되는 동안 규칙 scheduler를 pause한다. 이동 종료 시 조건이 여전히 맞으면 보존한 규칙 위치를 재개하되, 그동안 규칙 결정이 바뀌었다면 최신 결과를 우선한다.
6. 랜덤 후보 없음·누락 참조 fallback은 `RepeatWhileRequested`로 실행하되 정상 랜덤 항목은 `Once`를 유지한다.
7. 설정 화면에 `조건이 유지되는 동안 선택한 행동 전체를 반복합니다.`를 안내한다.

## 필수 자동 테스트

1. 앱 사용 규칙이 두 단계·서로 다른 단계 반복 횟수를 두 번 이상 순환한다.
2. 입력 없음 규칙이 저장 `repeats=true/false` 모두에서 조건 유지 중 반복한다.
3. 같은 snapshot을 1초마다 갱신해도 현재 재생 위치가 초기화되지 않는다.
4. 다른 앱으로 전환하거나 입력이 재개되면 사이클 중간에도 즉시 다음 결과로 바뀐다.
5. 앱·입력 없음 규칙 사이 우선순위 전환과 같은 종류 내 안정 순서를 유지한다.
6. 규칙이 이동보다 높을 때 이동 정지+규칙 반복, 이동이 높을 때 이동 표시+규칙 pause/복구를 확인한다.
7. 랜덤 후보 없음·누락 참조는 기본 행동을 반복한다.
8. fixed 연속, random 항목 1회, 쓰다듬기 1회, 이동 중 반복 회귀를 확인한다.
9. 행동 대사가 동일 행동의 반복 경계에서 중복 발생하지 않는지 확인한다.
10. Debug·Release 전체 테스트와 빌드, `git diff --check`를 실행한다.

## 실제 Windows QA

- 짧은 2단계 행동을 앱 규칙에 연결해 대상 앱을 전면에 둔 채 세 번 이상 자연스럽게 반복되는지 본다.
- 대상 앱을 벗어났다가 다시 돌아와 평상시 행동과 다른 규칙 행동이 첫 단계부터 시작하는지 확인한다.
- 입력 없음 임계값을 짧게 두고 세 번 이상 반복, 입력 즉시 해제와 재진입을 확인한다.
- 규칙이 이동 위/아래인 경우 좌표와 표시 행동을 각각 확인한다.
- fixed·random·쓰다듬기·세 이동 방식에 회귀가 없는지 확인한다.
- 저장·재실행 후 결과와 macOS의 같은 프로필 동작을 비교한다.
