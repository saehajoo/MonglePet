# Windows 행동 중심 모델 인계

## 목적과 경계

macOS에서 확정한 행동 중심 사용자 모델을 Windows C#·WinUI 3에 네이티브로 반영한다. SwiftUI 화면이나 AppKit 런타임을 복사하지 않고 공통 JSON 의미와 사용자 결과를 맞춘다. Windows 소스 변경·빌드·실기기 QA는 Windows 환경에서 수행한다.

## 확정한 사용자 결과

- 애니메이션은 프레임 자산이며 사용자가 자동·직접 선택, 이동과 쓰다듬기에 연결하는 단위는 행동이다.
- 행동은 변경 불가능한 ID와 변경 가능한 표시 이름을 가진다. 이름 변경은 모든 참조를 깨지 않는다.
- 행동 편집 화면은 행동의 생성·이름·애니메이션 단계·반복만 담당한다.
- `표시 및 이동` 화면에서 평상시 행동을 `하나 선택` 또는 `랜덤 선택`으로 고른다. 랜덤 선택은 행동 행 전체를 눌러 복수 선택한다.
- 종전 `자동 동작`은 `규칙 설정`으로 바꾸고 행동 모드를 제거한다. 이 화면에는 우선순위, 입력 없음 규칙과 앱 사용 규칙만 둔다.
- 입력 없음·앱 규칙은 하나 선택과 랜덤 선택 모두에 적용된다. 일치 규칙이 없을 때만 평상시 행동이 fallback으로 실행된다.
- 입력 없음 규칙은 하나만 두고 항상 보이는 사용 토글과 시간·행동 `변경` 버튼으로 편집한다. 앱 사용 규칙은 앱 식별자마다 하나씩 추가하며 입력 없음 섹션 아래에 둔다.
- 입력 없음 시간은 macOS처럼 `1...86,400초` 정수로 직접 입력하고 1초씩 감소·증가한다. 저장 계약은 `idleAtLeast.milliseconds`를 유지해 초 값에 1,000을 곱하며, 기존 분 단위로 저장된 값은 같은 시간을 초로 표시한다. 1초 주기 활동 감지에 따른 최대 약 1초의 진입·해제 감지 지연을 안내하되 임계값을 분 단위로 반올림하지 않는다.
- 이동·규칙 충돌은 `이동`, `입력 없음 규칙`, `앱 사용 규칙` 세 항목을 사용자가 위·아래로 정렬한 목록 순서로 결정하며 개별 숫자 우선순위는 노출하지 않는다.
- 표시 및 이동의 공통·방향별 선택과 쓰다듬기는 행동 목록을 사용한다.
- 펫 보관함에는 내장·읽기 전용·편집 가능한 펫 모두 `펫 사본 새로 만들기`를 항상 표시한다. 원본을 유지하고 새 패키지·설치·프로필을 선택한다.
- 편집 가능한 펫의 `애니메이션 복제…`는 하나의 진입점만 둔다. 누르면 복사본 편집 dialog가 열리고 원본 이름을 표시하며, dialog 안의 공통 `행동 연결`에서 연결 안 함·새 행동 만들기·기존 행동에 추가 중 하나를 고른다. dialog를 열기 전에 행동을 미리 만들지 않으며 저장을 확정 경계로 삼아 취소·창 닫기 시 복사본을 되돌린다. 복제 실패는 즉시 dialog로, 이름·프레임 간격·행동 연결 검증과 저장 실패는 스크롤 위치와 무관하게 하단 작업 버튼 바로 위 banner로 보여준다.
- 편집 가능한 펫의 애니메이션 추가·수정 dialog에는 공통 `행동 연결` 카드를 둔다. `연결 안 함`을 기본으로 하고 `새 행동 만들기` 또는 `기존 행동에 추가`를 선택하며, 수정에서는 현재 애니메이션을 사용하는 행동 이름을 보여준다. 새 행동은 저장된 애니메이션 한 단계의 반복 행동이고 기존 행동에는 반복 1회 단계를 마지막에 붙인다. 같은 단계가 이미 있으면 안내하되 허용하고 취소·창 닫기 전에는 행동 설정을 변경하지 않는다.
- `표시 및 이동`의 쓰다듬기·공통 이동·방향별 행동 ComboBox는 행동 표시 이름을 섞지 않고 한 단계 행동은 현재 애니메이션 이름, 현재 펫 기본 참조는 `기본 애니메이션`, 여러 단계 행동은 `첫 애니메이션 외 N개`로 표시한다.
- 애니메이션 저장 시 한 단계 행동의 표시 이름이 정확히 자동 생성 `… 복사본` 또는 `… 복사본 N` 형태로 남아 있으면 현재 참조 애니메이션 이름으로 동기화한다. 사용자가 직접 정한 이름, 여러 단계 행동, 기본 애니메이션 참조와 이름 충돌이 있는 행동은 유지한다. 행동 ID와 모든 참조는 바꾸지 않는다.
- 자유 이동 머무르기의 고정·최소·최대 시간 입력은 고정된 낮은 높이의 사용자 정의 필드로 감싸지 않는다. 네이티브 숫자 TextBox와 별도 `초` 단위, 동일한 감소·증가 버튼 폭을 사용해 100%~200% DPI와 좁은 창에서도 숫자의 위·아래가 잘리지 않아야 한다.
- 마우스 따라가기, 자유 이동과 마우스 도망가기의 모든 수치·시간 방식·방향 행동은 서로 독립이다. 도망가기의 `평상시 자유 이동`도 일반 자유 이동의 값이나 고정/랜덤 시간 방식을 공유하지 않는다. UI에서 이동 방식을 바꾸거나 한 값을 편집해도 다른 방식의 draft·저장값을 바꾸지 않는다.
- 펫 보관함의 `패키지 파일로 저장`은 모든 휴대 펫 옵션을 담은 권장 프로필을 항상 포함한다. 앱 규칙만 `pfn:`/`exe:` 식별자 노출 때문에 별도 선택한다.
- 패키지 저장·가져오기 확인 화면은 평상시 하나·랜덤 선택과 선택 행동, 조건 규칙의 전체·사용 개수, `이동`·`입력 없음`·`앱 사용` 우선순위, 따라가기·자유 이동·도망가기·도망가기 평상시 자유 이동의 독립 값과 휴대 표시 설정을 모두 요약한다. 상세 제목과 선택 문구도 `조건 규칙`, `앱 사용 규칙`을 사용한다. 행동·이동·쓰다듬기 참조는 안정 ID가 아니라 행동 `DisplayName`으로 표시하고 찾을 수 없는 참조도 원시 ID를 노출하지 않는다. `pfn:`/`exe:`는 앱 규칙 공유 동의에 필요한 경우에만 표시한다.
- 새 설치는 `펫만 설치 · 포함 설정 적용 안 함`과 `포함된 설정 모두 적용 후 설치`로 적용 범위를 구분한다. 제외 안내에는 모니터·좌표·모든 펫 공통 이동 범위·깨움·시작 프로그램만 두고 v10의 크기·투명도·클릭 통과·포인터 겹침·픽셀 표시는 포함 항목으로 표시한다.

## 공통 데이터

- 내장 몽글이 기준본은 `shared/BuiltInPets/Mongle.monglepet`의 펫 버전 `1.0.3`, 13개 모션·53프레임과 권장 프로필 v10이다. 기본 행동은 현재 펫의 `기본` 애니메이션, 입력 없음 60초는 `자는 중`, 우선순위는 `입력 없음→앱 사용→표시 및 이동`, 기본 앱 규칙은 없음, 쓰다듬기 행동 `행복`은 모션 `행복`을 사용한다. 세부 ID·이동·표시 값과 1.0.1/1.0.2 이관은 `WINDOWS_BUILTIN_MONGLE_HANDOFF.md`를 따른다.
- macOS 로컬 설정 현재 버전은 `SETTINGS_SCHEMA.md`의 schema-v15다. Windows 로컬 schema 번호는 기존 Windows 이력에 맞춰 순차 승격하되 아래의 독립 구조와 마이그레이션 결과를 동일하게 구현한다.
- 권장 프로필 현재 버전은 `PET_PACKAGE.md`의 schema-v11이며 플랫폼 공통 파일이므로 번호와 필드명을 그대로 사용한다.
- schema-v13은 `mode: random`, `randomSequenceIDs`, `randomizesFreeRoamingDwell`, `freeRoamingDwellMinimumMilliseconds`를 추가한다. v12 입력은 랜덤 목록 비움·랜덤 머무르기 끔으로 승격한다.
- schema-v14와 권장 프로필 v10은 `cursorFollowing`, `freeRoaming`, `cursorAvoiding`을 중첩 저장하고 도망가기 안에 별도 `idleFreeRoaming`을 둔다. v13/v9의 공용 속도·정지 반경·시간 방식·전면 창 선호는 관련 모드 각각에 복제한다.
- macOS schema-v15와 권장 프로필 v11은 `stationaryBehaviorMode: fixed | random`, `stationarySequenceID`와 독립 `automaticRules`를 사용한다. 기존 automatic은 fixed+null로 옮기고 규칙을 유지하며, manual·random은 평상시 선택을 보존하되 과거 휴면 규칙을 비활성화한다.
- 권장 프로필 v10 `display`의 `scalePercent`, `clickThrough`, `opacity`, `pointerOverlapFadeEnabled`, `pointerOverlapOpacity`, `pixelArtRendering`을 Windows overlay에 적용한다. Windows monitor/좌표, 모든 펫 공통 이동 범위, awake/tucked away, 시작 프로그램과 인스턴스 식별자는 보존한다. v1~v9에는 `display`가 없으므로 현재 Windows 표시값을 유지한다.
- v11 이하 설정과 권장 프로필 v1~v7의 이동·쓰다듬기 애니메이션 참조는 애니메이션별 반복 한 단계 행동으로 승격한다.
- 동일한 애니메이션을 참조하는 동등한 한 단계 행동이 이미 있으면 재사용한다.
- Windows 앱 식별자는 기존 `pfn:` / `exe:` 로컬 표현을 유지한다. macOS bundle identifier와 Windows 식별자를 플랫폼 간 권장 프로필에 무심코 공유하지 않는다.

## macOS 디자인과 Windows 시각 동등성

macOS 설정 화면의 현재 정보 구조와 시각적 위계는 Windows의 기준 디자인으로 사용한다. SwiftUI 화면을 픽셀 단위로 복사하거나 SwiftUI 수치를 무조건 C#에 옮기지는 않지만, 사용자가 두 플랫폼에서 같은 화면으로 인식할 수 있도록 다음 결과를 맞춘다.

- `데스크톱`, `선택한 펫`, `보관함` 탐색 그룹과 각 목적지의 순서, 화면 제목, 설명 문구와 주요 작업 순서를 macOS와 맞춘다.
- 섹션 카드의 묶음, 여백의 상대적 크기, 제목·보조 설명·현재 값·주요 버튼의 강조 단계, 전체 행 hit area와 비활성 상태의 의미를 맞춘다.
- 행동, 규칙 설정, 표시 및 이동과 펫 보관함은 macOS에서 확정한 최신 화면을 함께 보면서 좁은 창에서도 같은 정보 순서를 유지한다. 단순히 기존 Windows 컨트롤에 기능만 덧붙이지 않는다.
- 프레임 편집기는 `WINDOWS_MACOS_1_3_HANDOFF.md`의 고정 미리보기, 낮은 대비 투명 격자, 가운데 정렬, 프레임 추가 위치, 기능별 버튼 그룹과 동일 크기 기준까지 적용한다.
- Windows에서는 `NavigationView`, Mica, WinUI grouped card, 표준 `ToggleSwitch`, `ComboBox`, focus visual과 키보드·Narrator 동작을 유지한다. macOS 전용 toolbar, sheet 크기, SF Symbol과 시스템 폰트는 대응 WinUI 아이콘·Typography로 바꾼다.
- 색상이나 고정 픽셀을 복제하기보다 light/dark 테마, 100%·150%·200% DPI와 창 폭 변화에서 같은 가독성과 작업 밀도를 확인한다. 의도적으로 달라지는 항목은 Windows 작업 계획에 이유와 대체 UX를 기록한다.

따라서 완전히 동일한 OS 외형은 목표가 아니지만, 레이아웃과 작업 흐름은 매우 비슷하게 구현할 수 있다. 구현 전 macOS 실제 화면과 `apps/macos/MonglePet/SettingsView.swift`를 기준으로 화면별 대조표를 만들고, 구현 후 동일 사용자 시나리오의 양쪽 스크린샷을 나란히 검토한다.

## 런타임

쓰다듬기 일회성 행동은 항상 최상위다. 앱·입력 없음 규칙과 이동이 동시에 활성화되면 세 항목의 사용자 목록 순서를 따른다. 규칙이 `이동`보다 위면 현재 위치에서 좌표 이동과 이동 행동 scheduler를 멈추고 규칙 행동을 표시한다. 규칙이 해제되면 현재 위치를 기준으로 이동을 다시 시작한다. `이동`이 규칙보다 위면 이동 좌표와 이동 행동을 유지한다. 일치 규칙이 없으면 이동 행동이 평상시 행동보다 앞선다. 이동 계층이 실제 표시되는 동안 가려진 고정 평상시 행동 scheduler는 pause하고 복귀할 때 행동 단계·반복·사이클 남은 시간과 실제 프레임 위치를 이어간다.

랜덤 선택은 선택 행동들의 shuffle bag을 사용한다. 각 행동의 단계·반복 횟수는 유지하되 행동 목록의 `repeats`와 무관하게 한 번 통과한 뒤 다음 행동으로 넘어간다. 한 bag에서 모든 선택을 한 번씩 사용하고 둘 이상이면 직전 행동과 같은 첫 항목을 피한다. 설정 snapshot과 이동 tick마다 다시 추첨하지 않는다. 쓰다듬기 overlay 뒤에는 기존 선택과 bag을 이어간다. 이동 또는 일치 규칙이 시작되면 현재 랜덤 행동을 중단하고 bag의 다음 행동을 첫 프레임·첫 cycle로 준비하며, 이동·규칙 종료 뒤 과거 행동을 복원하지 않는다.

Windows의 고빈도 포인터·이동 tick마다 행동 scheduler·timer·Composition surface를 다시 만들면 안 된다. 이동 시작·종료 또는 해석 행동 ID 변경 때만 이동 행동을 전환하고, 같은 행동 ID의 반복 activity snapshot은 무시한다. 잠금·절전·전체 일시정지는 기본·이동·상호작용 timer를 함께 pause한다.

### 마우스 도망가기의 평상시 자유 이동 회귀 수정

과거 Windows `PetMovementRuntime.TickCursorAvoiding`은 포인터가 감지·해제 거리 밖에 있는 평상시에도 `_target = null`을 매 tick 실행한 뒤 `TickFreeRoaming`을 호출해 자유 이동 목표가 약 60Hz로 다시 추첨되는 회귀가 있었다. 현재 구현은 Core `CursorAvoidingPhaseState`를 런타임의 전환 단일 원본으로 사용해 도망 상태를 벗어나는 한 번의 tick에서만 도망 목표를 지우고 이후 평상시 자유 이동 목표와 dwell을 유지한다. 100회 반복 idle tick과 escape→idle 전환 회귀 테스트 및 설치 Release 사용자 확인을 통과했다. 기준 동작은 다음과 같다.

- 도망 중에는 포인터 위치에 맞춰 도망 목표를 갱신한다.
- 포인터가 해제 거리 밖으로 나가 `도망 중 → 평상시`로 전환되는 한 번에만 도망 목표를 버린다.
- 평상시 자유 이동에 들어간 뒤에는 현재 목표를 도착할 때까지 유지한다.
- 도착하면 고정 모드에서는 `freeRoamingDwellMilliseconds`, 랜덤 모드에서는 `freeRoamingDwellMinimumMilliseconds...freeRoamingDwellMilliseconds`에서 도착 시 한 번 뽑은 시간 동안 머문 뒤 다음 목표를 한 번만 만든다.
- 평상시 정지를 선택한 경우에만 목표·대기 상태와 이동 행동을 정리한다.

Windows 구현은 `CursorAvoidingPhaseState.IsEscaping`과 `EnteredIdle` 전환값으로 전환 순간과 이미 평상시인 tick을 구분한다. 이미 평상시 자유 이동 중이면 `_target`, `_dwellUntil`과 논리 좌표 누적기를 초기화하지 않는다. 도망 상태를 빠져나오는 첫 tick에는 도망 목표만 지우고 현재 실제 위치를 기준으로 자유 이동 목표를 한 번 만든다. 기존 60Hz 논리 좌표 누적, 이동 속도, 정지 반경과 방향 행동 전환은 유지한다.

## 구현 순서

1. C# Domain에 행동 `Id`, `DisplayName`, 자동 규칙 종류와 종류 우선순위를 추가한다.
2. schema-v12 행동 승격과 schema-v13 랜덤 기능 뒤 독립 이동 구조의 다음 Windows schema와 종전 공유값 복제 마이그레이션을 구현하고 공통 fixture를 통과시킨다.
3. recommended-profile v11 codec, v1~v10 승격·표시 미적용 호환과 미래 버전 선택 데이터 격리를 구현한다.
4. 기본·이동·쓰다듬기 playback을 분리하고 표시 우선순위를 연결한다.
5. WinUI 정보 구조를 `행동`, `규칙 설정`, `표시 및 이동`으로 맞추고 좁은 창·키보드·Narrator를 확인한다.
6. 모든 펫 사본 생성과 현재 인스턴스의 프로필 복사를 연결한다.
7. 애니메이션 추가·수정·복제본 dialog의 단일 행동 연결 선택, 현재 사용 행동, 고정 하단 오류 banner, 이름·한도 검증과 저장/취소 경계를 구현한다.
8. 패키지 저장에 전체 휴대 설정을 항상 포함하고 가져오기 전체 적용을 한 번의 settings 저장으로 연결한다.
9. `마우스 도망가기 + 평상시 자유 이동`의 목표 수명 회귀를 수정하고 반복 tick 테스트를 추가한다.
10. macOS 기준 화면과 Windows 결과의 화면별 시각 대조 및 DPI·테마 QA를 수행한다.

## 필수 자동 검증

- v11 이동·쓰다듬기 애니메이션이 중복 없는 한 단계 행동으로 승격되고 재저장하면 v13이 된다.
- 랜덤 선택의 한 bag에 고른 행동이 각각 한 번만 나오고, 행동 경계 이외의 snapshot·이동 tick·상호작용 overlay가 재추첨하지 않는다.
- 고정/랜덤 머무르기와 최솟값·최댓값이 왕복되고 도착 한 번당 난수 샘플도 한 번만 소비한다.
- 자유 이동과 도망가기의 평상시 자유 이동에 서로 다른 고정/랜덤 방식·최소/최대·속도·정지 반경·전면 창 선호를 저장한 뒤 이동 방식 전환·재실행·권장 프로필 왕복에서도 서로 바뀌지 않는다.
- 행동 표시 이름 변경 뒤 직접 선택·규칙·이동·쓰다듬기·말풍선 참조가 유지된다.
- 입력 없음 규칙 중복과 같은 앱 식별자 규칙 중복을 거부하거나 안전하게 하나로 복구한다.
- 이동·입력 없음·앱 사용의 모든 목록 순서가 저장·복원되고, 일치 규칙이 이동보다 앞이면 좌표 이동·이동 scheduler가 멈추며 규칙 해제 후 현재 위치에서 재개된다. 이동이 앞이면 좌표 이동과 이동 행동을 유지한다.
- 100회 동일 이동 tick에 scheduler 시작·timer 예약이 한 번뿐이며 방향 행동 ID가 바뀔 때만 다시 시작한다.
- 쓰다듬기 종료 시 이동/정지 상태에 맞게 복귀하고 기본 행동 진행 위치가 유지된다.
- 내장·읽기 전용·편집 가능 원본의 사본 생성 뒤 원본 파일·설정이 바뀌지 않는다.
- 애니메이션 추가·수정·복제본에서 연결 안 함, 한 단계 새 행동, 기존 행동 마지막 단계 추가가 각각 저장되고 취소 시 행동이 바뀌지 않는다. 복제 dialog를 여는 동안 행동은 생기지 않고 취소 시 복사본만 제거된다. 이름 중복·행동/단계 한도는 패키지 변경 전에 하단 banner로 차단하며 같은 애니메이션 중복 단계는 안내 뒤 허용한다.
- macOS가 내보낸 권장 프로필 v11의 모든 독립 이동·평상시 행동·조건 규칙·말풍선·휴대 표시 값을 Windows가 읽고 다시 내보낸 결과를 macOS가 같은 의미로 읽는다. v10 입력의 기존 직접·랜덤 선택과 휴면 규칙 마이그레이션 결과도 양쪽에서 일치해야 하며 v9 입력 적용은 현재 표시 설정을 유지한다.
- 패키지 파일 저장 결과에 `recommended-profile.json`이 항상 있고, 앱 규칙 포함을 끄더라도 나머지 모든 휴대 옵션이 유지된다. 적용은 대상 펫만 바꾸며 monitor/좌표/공통 이동 범위/깨움 상태를 보존한다.
- 포인터가 계속 감지 거리 밖인 상태에서 도망가기의 평상시 자유 이동 tick을 100회 실행해도 목표는 한 번만 생성되고, 도착 전에는 바뀌지 않는다.
- 도망 상태에서 해제 거리 밖으로 나가는 첫 tick에는 자유 이동 목표를 한 번 새로 만들고, 다음 tick부터 같은 목표를 유지한다.
- 자유 이동 목표에 도착하면 설정된 대기 시간이 끝나기 전에는 새 목표를 만들지 않고, 대기 종료 후 정확히 한 번 만든다.
- 평상시 정지를 선택하면 도망 해제 뒤 좌표와 이동 행동이 안정적으로 멈춘다.

## 실제 Windows QA

- 실제 WinUI 설정에서 sheet/dialog 기반 행동 생성·이름 변경·단계 편집, 직접·랜덤 복수 선택, 입력 없음 토글, 앱 규칙과 종류 순서를 확인한다.
- 펫 크기는 192pt 기준 100%와 10~200% 범위, 5% 슬라이더·직접 입력과 10·25·50·100·150·200% 빠른 선택을 macOS와 같은 의미로 제공하되 Windows DPI 단위로 렌더링한다. 25% 미만에서는 찾기·드래그가 어려울 수 있다는 안내와 notification area의 `현재 화면으로 가져오기` 복구 경로를 함께 보여준다.
- 자유 이동과 도망가기의 평상시 자유 이동에서 상단 `고정/랜덤` 선택, 같은 크기의 0.5초 감소·직접 초 입력·증가 컨트롤과 최소·최대 관계를 확인한다. 직접 입력과 증감은 재실행 뒤에도 남도록 즉시 또는 편집 완료 시 원자적으로 저장한다.
- 마우스 따라가기·자유 이동·도망가기의 4/8방향 행동과 쓰다듬기 우선순위를 실제 펫으로 확인한다.
- 마우스 도망가기의 평상시 행동을 `자유 이동`으로 두고 포인터를 멀리 둔 상태에서 펫이 한 목표까지 부드럽게 이동하고 설정한 시간만큼 머무는지 확인한다. 포인터를 감지 거리 안팎으로 반복 이동해도 도망 해제 후 목표가 매 프레임 바뀌거나 춤추듯 흔들리지 않아야 한다.
- macOS와 Windows에서 행동·규칙 설정·표시 및 이동·펫 보관함의 같은 사용자 시나리오를 캡처해 정보 순서, 카드 묶음, 버튼 강조, 행 hit area와 미리보기 배치를 나란히 확인한다. `표시 및 이동`은 `설정 대상 펫`, 별도 `펫 깨우기`, 화면 표시, 평상시 행동, 이동 방식, 기본 설정, 모든 펫 공통 이동 범위 순서를 유지한다. 픽셀 아트·클릭 통과·겹침 투명도, 정지 반경과 방향별 행동은 접는 고급 영역을 만들지 않고 해당 섹션에서 항상 표시한다.
- Windows light/dark, 100%·150%·200% DPI, 좁은 창, 키보드와 Narrator에서 잘림·겹침·접근 불가 항목이 없는지 확인한다.
- 기존 schema-v11~v13 의미의 사용자 데이터와 보관함을 보존한 업데이트·재실행을 확인하고 세 이동 방식의 값이 최초에는 종전 동작과 같다가 이후 독립 편집되는지 확인한다.
- Release에서 이동 프레임 부드러움을 유지하며 CPU, private memory, timer 수와 장시간 증가량을 비교한다.
- Windows 구현과 실기기 QA 전에는 `PLATFORM_PARITY.md`에서 동등 완료로 표시하지 않는다.
