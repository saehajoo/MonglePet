## 1. 행동 삭제 시 모든 독립 이동 설정 보존

삭제 대상 행동을 제거할 때 기존 프로필을 복사하고 해당 행동의 참조만 정리한다. 구형 공용 속도·시간·행동 필드로 최신 이동 설정을 새로 만들지 않는다.

- `cursorFollowing`: 속도, 마우스 거리, 정지 반경, 공통/방향별 행동 및 방향 사용 상태
- `freeRoaming`: 속도, 정지 반경, `dwellMode`, 최소/최대 머무르기, 전면 창 선호, 공통/방향별 행동 및 방향 사용 상태
- `cursorAvoiding`: 감지 거리, 도망 속도, 정지 반경, 평상시 이동 방식, 공통/방향별 행동 및 방향 사용 상태
- `cursorAvoiding.idleFreeRoaming`: 일반 자유 이동과 별도의 위 자유 이동 설정 전체

각 모드에 필요한 모든 기존 필드를 보존하며 선택되지 않은 모드도 같은 기준을 적용한다. 삭제한 행동이 참조된 공통/방향 필드만 비운다. `behaviorCompletion`을 고정 또는 랜덤으로 바꾸거나 다른 모드의 시간으로 덮어쓰면 안 된다. 이동·표시·말풍선의 무관한 필드와 다른 펫의 instance/profile은 그대로 유지한다.

최소 기본 행동은 계속 삭제할 수 없다. 고정 평상시 선택이 삭제 대상이면 기본 행동으로 복구하고 랜덤 후보에서는 일치 ID만 제거한다. 기존 정책대로 해당 행동을 참조하는 조건 규칙과 행동 대사를 제거하고 쓰다듬기 연결을 해제한다. 나머지 행동·규칙·규칙 종류 순서·주기 대사·말풍선 설정은 유지한다.

## 2. 삭제 전 실제 영향 확인

삭제 버튼에서 곧바로 변경하지 않고 해당 펫과 행동의 영향 요약을 확인한다. 요약은 실제 현재 프로필에서 계산하며 내부 UUID·함수명 대신 사용자 표시 이름과 개수를 사용한다.

- 고정 평상시 행동이 기본 행동으로 바뀌는지, 랜덤 후보에서 빠지는지
- 이동 방식별 공통·방향 연결과 쓰다듬기 연결 중 어느 것이 해제되는지
- 함께 제거되는 조건 규칙과 행동 대사의 이름 또는 내용, 각각의 개수

연결이 없는 경우 불필요한 영향을 만들어 표시하지 않는다. 취소하면 행동·설정·선택을 변경하지 않는다. 확인한 대상과 실제 삭제 대상을 같은 안정 ID로 묶고 삭제 직전에 최신 상태를 다시 검증한다. 경고는 삭제를 시작한 편집기에서 확인할 수 있어야 하며 다른 설정 페이지의 오류 영역에만 표시하면 안 된다.

## 3. 설정창 공통 저장 실패 안내와 재시도

유효한 설정 편집은 기존처럼 즉시 메모리와 runtime에 반영한다. 디스크 저장 실패 시 메모리의 최신 값을 보존하고 모든 설정 목적지에서 같은 실패 안내와 `다시 저장`을 보여준다. 재시도는 실패 당시 snapshot이 아니라 버튼을 누른 시점의 최신 유효 설정 전체를 저장한다.

- 기존 원자적 settings 저장, 검증, 크기 제한과 미래 schema 쓰기 차단을 그대로 사용한다.
- 재시도 성공 때만 오류를 없애고, 실패하면 현재 값과 실패 안내를 유지한다.
- 탭·선택 펫 이동 뒤에도 오류가 사라지거나 이전 상태를 저장하지 않아야 한다.
- 저장 실패 상태와 필요한 설정 변경만 ViewModel에서 알린다. 좌표·프레임·이동 tick이나 행동 진단을 화면 재구성·재저장에 연결하지 않는다.
- 기존 가져오기·새 펫·사본 만들기의 installation/settings transaction 실패 rollback은 이 일반 설정 재시도와 별개로 유지한다.

Windows에서는 앱 수명의 저장 서비스 또는 settings session에 실패 상태를 두고 WinUI 설정 셸의 공통 `InfoBar`와 재시도 명령으로 연결할 수 있다. 페이지 인스턴스가 실패 snapshot을 따로 소유하거나 timer로 설정 전체를 다시 바인딩하지 않도록 한다.

## 4. 큰 제작 편집기의 미저장 초안 보호

대상은 새 펫 만들기, 애니메이션 추가·수정·복제, 현재 펫 프레임 선택, PNG crop, 스프라이트 가져오기와 말풍선 모양·위치 편집이다. 초안 초기값과 현재 저장/반영 결과를 비교하는 변경 감지를 사용한다.

- 이름·행동 연결·프레임 순서/간격/배치/뒤집기·가져올 프레임 포함/선택 순서·crop·말풍선 값의 실질 변경만 감지한다.
- 확대·스크롤·초점·미리보기 재생만 바꾼 경우와 값을 원래대로 되돌린 경우에는 바로 닫는다.
- 변경한 초안에서 해당 편집기의 취소 버튼과 제목바 X는 같은 `계속 편집` / `변경사항 버리기` 확인을 거친다. 계속 편집하면 초안·상위 창·입력 상태를 유지한다.
- 부모 창·앱 종료에 따른 자식 창의 즉시 종료는 기존 수명 정책을 유지한다. 해당 종료 경로의 초안 보호는 이번 구현 범위와 완료 조건에 포함하지 않는다.
- 해당 편집기의 기존 완료 경계에서 저장 또는 상위 초안에 추가가 성공하면 한 번의 승인된 종료로 처리해 폐기 확인을 다시 띄우지 않는다. 초안 검증·패키지 저장 실패처럼 완료하지 못한 경우에는 편집기와 오류를 유지한다.
- 폐기 안내는 `아직 저장하지 않은 변경사항은 사라집니다. 저장 도중 일부만 적용된 경우 이미 저장된 내용은 유지됩니다.`를 사용한다. 버리기는 아직 반영하지 않은 초안·임시 작업을 정리하며 이미 완료된 저장까지 자동으로 되돌리는 기능이 아니다. 애니메이션 복제 등 각 기능의 기존 취소 rollback 경계는 유지한다.
- macOS의 기존 애니메이션 수정은 패키지 저장 후 행동 연결·이름 동기화가 실패하면 창은 유지하지만 이미 저장된 애니메이션은 남는다. 저장을 시도하기 전의 단순 취소와 일부 저장 후 남은 초안의 폐기를 구분해야 한다. Windows도 실제 기존 commit·rollback 경계를 확인하고 보장할 수 없는 전체 원복을 안내하지 않는다.
- 말풍선 모양·위치는 메모리 반영 후 디스크 저장 실패 시에도 기존대로 창을 닫고 공통 저장 실패 안내·재시도로 복구한다. 이런 설정 적용을 패키지 검증 실패와 동일하게 처리하지 않는다. 이번 작업은 저장 transaction 전체의 원자성 재설계가 아니다.

macOS의 AppKit delegate나 SwiftUI 코드를 직역하지 않는다. Windows는 소유한 WinUI 제작 창의 `AppWindow.Closing`, 취소 명령과 현재 `XamlRoot`의 네이티브 확인 경계를 연결한다. 비동기 확인 중 중복 닫기·재진입을 막고, 저장 성공의 programmatic close는 한 번만 확인을 우회한다. OS 강제 종료·비정상 종료의 영구 초안 복구는 이번 계약에 포함하지 않는다.

## 필수 자동 검증

1. 네 독립 이동 설정에 서로 다른 값을 넣고 미참조 행동을 삭제해 이동 설정 전체의 전후 동일성을 확인한다. 비활성 모드와 두 `behaviorCompletion` 값도 포함한다.
2. 모드별 공통/8방향 참조 중 삭제 ID만 해제하고 다른 참조·모드 값·표시·쓰다듬기·말풍선 설정이 보존되는지 확인한다.
3. 고정/랜덤 선택, 연결된 조건 규칙·행동 대사와 실제 삭제 영향 요약이 일치하고, 취소·기본 행동 삭제 거부가 데이터를 바꾸지 않는지 확인한다.
4. 수정된 프로필을 저장·재로드하고 제작자 설정 v12 내보내기·가져오기에서 독립 값이 유지되는지 확인한다.
5. 저장 실패를 주입해 메모리 최신 값 유지, 공통 오류, 재시도 성공 후 디스크 재로드를 확인한다. 첫 실패 뒤 추가 편집한 값이 재시도에 반영되고 재실패·쓰기 차단이 안내를 숨기지 않는지도 확인한다.
6. 변경 없음·변경 있음·원복한 초안·표시 전용 조작을 구분하고, 해당 편집기의 취소·제목바 X·계속 편집·버리기·저장 성공·저장 실패 경로를 검증한다. 확인 중복과 복제 임시 상태 누락도 확인한다. 애니메이션 패키지 저장 후 연결 갱신 실패의 부분 적용과 말풍선 메모리 반영 후 디스크 실패의 공통 재시도를 각 기존 경계에 맞춰 별도로 검증한다.
7. 위 변경과 관련한 기존 Domain·Settings·편집기 테스트, Windows Debug·Release 빌드와 `git diff --check`를 실행한다. 패키지와 settings의 기존 schema 값도 유지되는지 확인한다.

## 실제 Windows QA와 교차 확인

- 실제 사용자 펫을 수정하지 않는 격리 설정·테스트 펫에서 따라가기·자유 이동·도망가기·도망가기 평상시 자유 이동을 서로 다르게 구성한다. 무관한 행동 삭제 후 모든 값과 움직임을 비교한다.
- 삭제 영향 dialog에서 규칙·대사 제거와 연결 해제가 구분되고 취소가 안전한지 확인한다. 긴 이름, 좁은 창, 다크/라이트, 100%·150%·200% DPI, 키보드와 Narrator도 확인한다.
- 쓰기 실패 주입 후 다른 설정 탭과 펫을 선택하고 값을 추가 변경한 뒤 재저장·재실행해 최종 값이 보존되는지 확인한다.
- 큰 제작 창과 중첩 PNG/스프라이트 창 각각의 취소·제목바 X·계속 편집·버리기, 저장 성공/실패를 확인한다. 계속 편집 선택 뒤 초안과 포커스가 유지되고 성공한 작업에 중복 경고가 없는지 확인한다. 일부 애니메이션 저장 후 남은 초안을 버렸을 때 이미 저장된 결과가 유지되는지, 말풍선 적용 후 디스크 실패는 창 밖 공통 안내에서 재시도할 수 있는지 구분한다.
- 펫 이동 중 설정 입력·스크롤·sheet와 제작 창을 사용해 저장 안내 도입이 runtime 구독이나 UI 재생성을 유발하지 않는지 확인한다.
- macOS→Windows→macOS 제작자 설정 v12 왕복으로 독립 모드 값과 삭제 후 남은 참조를 비교한다. 단위 테스트 통과와 실제 교차 QA 완료는 따로 보고한다.

## 유지하는 경계와 완료 보고

부모 창·앱 종료에 따른 자식 창의 즉시 정리는 미저장 확인을 우회할 수 있다. macOS의 기존 `closeImmediately` 수명 정책을 이번에 변경하지 않았으며 Windows도 이 작업의 편집기 자체 닫기 보호를 전체 앱 종료 보호로 보고하지 않는다. 이 경로의 초안 보호와 부모/자식 종료·복제 임시 상태 정리 QA는 별도 후속 위험으로 추적한다. 강제 종료·비정상 종료의 영구 복구를 제공한다는 의미도 아니다.

애니메이션 패키지와 행동 연결을 별도로 저장하는 기존 경계에는 부분 성공이 남을 수 있다. 이번 폐기 보호는 이미 적용된 내용을 원복하지 않으며, 편집 전후를 하나의 transaction으로 묶는 강화 작업은 후속 검토로 남긴다. 실제 플랫폼의 완료·실패 경계와 사용자 안내가 다르면 해당 차이부터 기록한다.

settings schema-v16, 제작자 설정 schema-v12, `.monglepet` formatVersion, 이미지 픽셀·atlas·원본 자산, 이동 cadence와 재생 정책을 바꾸지 않는다. 실행취소·영구 백업·행동 전체 미리보기·새 성능 최적화·WebP·20~30 MiB 최소 앱 버전 정책·자동 업데이트는 별도 작업이다. 별도 요청 없이 앱 버전·빌드, 커밋·푸시와 릴리스를 진행하지 않는다.

완료 후 변경한 Domain·저장·UI 경계, 보존/실패 주입 테스트 결과, Debug·Release 결과, 실제 Windows·교차 QA, 남은 위험과 Git 상태를 구분해 보고하고 본 인계서·관련 작업 계획·`PLATFORM_PARITY.md`를 갱신한다. 다른 작업의 기존 통과 기록으로 이 작업의 검증을 대신하지 않는다.
